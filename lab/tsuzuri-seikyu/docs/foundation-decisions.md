形：`<法則・理論の ID>：事実 → 決めたこと（理由の原理）`。動きは 5 つの役（応答・手がかり・待ち・誘導・らしさ）のどれかを書く。

## 構造・層
S-04：基本の部品は業務の言葉を知らない・請求書の状況を表したい → 状況→呼び名と札の調子は `parts/status.ts` 1 か所、基本の StatusTag は `tone` だけ受ける（T-3・S-09）

S-02：一覧が請求書・取引先・入金・レポートの内訳で 4 画面に出る → 表を 2 画面目で DataTable にまとめた（同じ決めごと＝幅で行に組み替える。T-3）
S-03：10 人が別々に作る・状況の呼び名が複数画面に出る → 呼び名は terms.ts / status.ts から引かせる。避ける言い方はテストで検出（T-3・T-6）
S-05：ボタンは種類だけ違う → variant 1 つの列挙。アイコンは `leading` で渡す。まだ要らない size は作らない（T-7・T-4）
S-05：「内容を確かめて送る」と「送る」を別ボタンにしたい → 画面側。基本の部品に確認つきボタンは作らない（振る舞いが違う＝別部品、T-2）
S-07：読み込み・空・失敗・成功は同時に 1 つ → `Fake<T>` の判別共用体。真偽値を並べない（T-7）
S-08：表の組み替えは部品の置かれた枠で決まる → コンテナクエリ `@2xl`（672px）。画面幅の `md:` は AppShell だけ（T-5）
S-09：標準の属性を渡す → Button・TextInput・Select などは残りの props を中の要素へ。`className` は外側の配置だけ（T-5）
S-10：Dialog の操作帯は「やめる→主」・スマホは縦に積む → DOM の順と見た目の順を同じにする（`flex-col-reverse` を使わない）

D-13：横の境目は端末名でなく中身で決める → 1024px でサイドメニュー、768px で主操作を見出しの右、表は枠 672px（P-4）

## 状況の色と札（taste の 5 つの役に寄せた）
A-02：状況は色だけで伝えない → StatusTag は絵＋言葉。6 つの調子 wait/progress/fail/done/calm/draft（手がかり・P-7）
D-04：期限超過は人が督促を判断する → wait（人の確認待ち・hand）にした。taste の「遅れ・止まっている」quiet は使わない（人が何もしなくてよい、ではないため）
D-04：下書きは「完了」ではない → calm（check）でなく draft（pencil・quiet）を足した
A-04：送付済みを「作業中」に寄せるが、30 行の表で回り続けるのは邪魔 → 札の絵は止める。回るのは処理中のボタンだけ（N-1・A-04）
D-05：「送る」と「発行」は同じ操作 → 呼び名は「送る」1 つ。番号は送るときに付く。画面は「内容を確かめる」→窓の「請求書を送る」（W-29・R-17）

## 動き（5 つの役）
A-01（応答）：ボタンを押した → `active:` で 2% 縮み＋1 段濃く（brightness）、押した瞬間は `--dur-instant`、戻りは `--dur-quick`。乗せたときは色を 1 段（`hover:`、タッチでは効かない）
A-01（手がかり）：キーボードで選んだ → 全体の `:focus-visible` の輪（藍 2px、offset 2）。乗せたときと別の見え方
A-01（応答）：処理中 → ボタンの幅を変えない（通常の文言と処理中の文言を重ねて長いほうに固定）、`aria-busy`、押しても何も起きない。`aria-disabled`（選択が外れないように）
A-03（待ち）：骨組みは 0.3 秒たってから現れる（`--delay-wait`、`animate-wait-in`）。動かさない。`role=status` と読み上げ用の文言
A-03（待ち）：待ちの印は回る → `--dur-spin` を足した（回り続ける動きの周期は tokens の時間の段に無い）。動きを減らす設定で止める（`motion-reduce:animate-none`、`--dur-spin: 0`）
A-07（応答）：Switch・Checkbox → 押した瞬間に `--dur-instant`、つまみは位置でも分かる（`--dur-quick`）。入力欄の枠の色は `--dur-instant`
A-04（誘導）：窓の出入り → 出るとき 8px 上がりながら濃くなる（`--dur-base`、`--ease-enter`）、スマホは下から。閉じる動きは付けない（標準の dialog は即閉じる。出るほうは短いほうが良い：N-4）
A-04（誘導）：短い知らせ → 下から 8px 上がって現れる（`--dur-base`）。消えるのは即時。失敗の知らせは閉じるまで残す。「元に戻す」つきは 10 秒、ほかは 6 秒（保つ時間であって動きの長さではない）
A-05：タブ・絞り込み・ページ送りの切り替え → 動かさない（1 日に何度も行う：N-8）。誤りは揺らさず、色・言葉・絵と、最初の誤り欄への移動で知らせる
A-06（らしさ）：性格は「静か」＝トークンのまま（跳ねない）。印になる動きは土台では置かない（画面の工夫の余地として残す。完了の場面の 1 つだけ）

## 言葉・形式
W-14：ボタンは押すと何が起きるかを言う → actions に集約（請求書を作る／下書きを保存／内容を確かめる／請求書を送る／入金を記録する…）。同じ操作は最後まで同じ名前
R-17：避ける言い方 → terms の avoid（22 組）。文字列に出たらテストが失敗する。設計の言葉も同じ
M-20：金額・日付・「N分前」は Intl だけで 1 か所（format.ts）。暦日は日本時間の正午に固定してずれを防ぐ
T-02：見本の「いま」を固定 → `NOW=2026-11-13 09:30 JST`。期限超過・「N分前」が毎回同じになる
M-09：読み込み・空・失敗を 1 つの戻り値で → useFake。error は再試行で待ちを経て default に立ち直る（待ちは 600ms の見せかけ）
M-34：名義の突き合わせの前に NFKC・かっこ・空白をそろえる → `normalizeName` 1 か所（半角カナも拾う）
R-09：入力の規則は表にして画面と検査で共有 → 土台では型と見本まで。入力規則の表は各画面の担当（郵便番号は 7 けた、金額は整数）

## 第1.5段で変えたこと（上の記録は消さず、変えた判断をここに足す）
新しい理論に当てて直した。形は同じ：`<ID>：事実 → 決めたこと（理由）`。

### 主操作・入力
F-10：入力画面で主操作が見出しの右だと欄より先に Tab が届く（S-10） → AppShell が `kind`（view/form）を必須で受け取る。form は 768px 以上で入力の末尾の右、768px 未満は下に固定。やめる→主（P-7・S-10）
D-05：窓の操作帯・下の固定帯・入力画面の末尾は「やめる→主」、縦に積むときは主が下 → Dialog の `actions` を廃止し `secondary`／`primary` を別の口にして、順を型で守る（B-06）
F-03：必須が全体の半分より少ない／任意が半分以下／全部必須で印が変わる → Field に `mark`、数え方は `markFor` 1 か所。「任意」の印を足した（I-21）
F-04：誤りが 2 件以上で先頭に一覧、フォーカスは最初の誤り欄、一覧は role=alert で focus を奪わない → `ErrorSummary`（CMP-031、Notice の形を再利用）と `useFocusFirstInvalid`。描き直し前に focus を呼ぶと欄がまだ invalid でないので、試行回数を数えて描き直しのあとに移す
F-05：金額は `type=text`＋`inputMode=numeric`、他人の情報に autocomplete を付けない → 手引きと番人（`type="number"`・`placeholder` を止める）。Field に `id`（まとめの一覧のリンク先）

### 数と日付
G-05：`Intl` の負の符号は半角ハイフンで、欠損の「—」と見間違える → `formatNumber` の末尾で U+2212 に替える 1 か所。Money の `tone="bad"` を廃止（負の金額も数字は色を付けない：C-06）
G-06：欠損を 0 にしない → `formatNumber`／`formatYen`／`Money` は `null` を受け、「—」（Money は読み上げ「データなし」）。`?? 0`・`|| 0` を番人が止める（数え始めの `(x ?? 0) + 1` だけ許す）
G-07：相対の時刻は 24 時間未満だけ → `formatAgo` は 60 秒未満「たったいま」、24 時間未満「N分前」「N時間前」、それ以上は「11/12(木) 15:20」（今年でなければ年つき）。一覧の列は `formatDateColumn`（今年以外が 1 件でもあれば全行を長い形）
L-10：数字と「件」の間の空白 → Pagination を「全120件のうち1〜20件」に、Stepper の読み上げも空白なしに

### 状況の調子
C-02：期限超過は人が督促を決める → wait（手）のまま。取り消し済みは calm、下書きは draft（pencil）。状況の表を下に置いた（CK-12 は parts.test が terms と照合）
C-04：一区切りの絵が完了と同じ（circle-check） → `circle-minus` を足して別の絵に。調子ごとに絵が 1 つずつ別（番人が 6 種を確かめる）。札の中の絵は回さない（progress の refresh-cw は止めた絵）
C-08：札が何十も並ぶ → StatusTag に `density`（normal／plain／quiet）、`tagDensityOf` が見えている札の調子から決める。5 枚以下は通常、6〜9 枚は太字を wait・fail だけ、10 枚以上は wait・fail 以外を静かな札に、1 つの調子が 80% 以上なら多数派を静かに。80% の行は下限が書かれていないので、6 枚以上に適用した（足した判断）
C-05：藍の下地の上の札は地を外す → `density="quiet"`

### 文言
L-03：保存が 2 種ある → 「下書きを保存する」「保存する」と語尾をそろえた。「書き出す」は対象が無いので「表を書き出す」（`exportFile`→`exportTable`）
L-06：ErrorState の例に直し方が無かった → 「〜ませんでした。」の文は直し方を持つことを番人が見る。useFake の既定の誤りの文は「もう一度読み込んでください」で終わる
L-02：avoid は日本語だけ → 「請求書」の avoid から英字の「invoice」を外した。制度の語「適格請求書発行事業者」は avoid の「発行」を含んでも書ける（番人が許す語）。メニューの「設定」が terms に無かったので足した
L-13：全画面で同じ語は terms.ts／status.ts から引き、画面にしか出ない文は画面ファイルに置いてよい（連結せず差し込む）。手引き 4.6 に書き、番人（直書きと `+` 連結）が止める。probe の「全て」は「すべて」に決めた

### 状態
E-02：土台の 18 語を共通の語彙へ寄せた（draft→status_draft、overdue→status_overdue、paid→status_paid、diff→status_diff、sending・exporting→saving、edit→mode_edit、step2・step3→step_2・step_3、zip_multi→zip_many、zip_none→zip_empty、no_candidate→candidates_empty）。画面が 1 枚も作られていないので影響なし
E-01：5 軸で見直して足した状態：conflict（設定・請求書の作成。REQ-011 が明記）、status_void と invalid（請求書の詳細）、confirming（入金の確認。まとめて確認）、filtered_empty（売上レポートの期間が 0 件）、todo_empty（ホームの今日やることが 0 件）、refreshing・stale（並べ替え・ページ送り・期間の切り替えのある一覧とレポート）
E-03：none の理由を、数字・「必ず」「固定」・REQ の ID のどれかを含む書き方に直した（番人 STATE-NONE）。全画面共通の forbidden・expired は REQ-011 を指す
E-04：useFake に `refreshing`（前のデータを持った待ち）と `stale`（前のデータ＋`asOf`＋再試行）を足し、`filtered_empty` は `kind=empty`（`state` で区別）にした。それ以外の新しい名前（invalid・saving・conflict・expired・resumed・done・status_＊・mode_＊・step_N・zip_＊・＊_empty）は成功として返り、画面が state を見て作る
