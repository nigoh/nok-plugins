## 3. 判断の記録
- D-01：状況の値 6（すべて・下書き・送付済み・期限超過・入金済み・取り消し済み）・5 を超える → タブにせずセレクト。件数は選択肢の文に入れる
- D-02：並べ替えの選択肢 6・選んですぐ反映・見比べない → セレクト（2〜3 個ではないのでセグメントにしない）
- D-04：主ボタン 1（請求書を作る・別の画面へ行くので LinkButton）。「条件をすべて外す」は条件のチップと同じ副（枠）のボタン → quiet にしない（今回直した）。行の取引先名は Link
- D-05：見出しの右のボタン 1 個・最長 6 字 → 横も縦も不要。外す条件のチップは折り返してよい種類（行頭をそろえ、間は 8px）
- D-06：文字の段 3（14・16・22px、ui-audit で測った）→ 補足（番号・請求日）も 14px の `muted`。12px は使わない
- D-07：刻みに無い余白 0／510 か所（ui-audit）→ 区画の間 24、欄どうし 16、チップどうし 8
- D-09：取引先名の最長 60 字 → 折り返して全部見せる。数字と単位・日付と曜日は折らない
- D-10：適用中の条件は条件を変える欄の直下に常に出す → ポインタを乗せたときだけ出る表示は使わない
- D-11：状況・日付・金額を同じ軸で見比べる → 表。枠 672px 未満は 1 行ずつの形（DataTable）。面（カード）にしない
- D-13：列 5 つにすると 672px で取引先の幅が 96px（672−32−16×4−128×3−96）で 6〜7 字で折れる → 4 列（取引先・状況・支払期限・税込金額）にし、請求日と番号は取引先の下の補助行に置く。欄は 768px 以上で横 3 つ（内側 704px で探す欄 192px）、未満は縦に積む
- D-14：主役は一覧・主操作あり → 3 欄の次に件数の行と一覧の頭を置き、説明・知らせは置かない（stale のときだけ一覧の上に 1 つ）
- E-02：状態名は screens.yaml のまま → 画面で足さない。`filtered_empty` は専用の取得を持たず、条件を URL に入れた本物の絞り込みで 0 件にする
- E-04：`refreshing`・`stale` で確定する操作が 0 個 → 前の一覧を残し、止めるのは並べ替えとページ送り（`disabled`）だけ。理由を「更新しています」の続きに書く
- E-05：初回 0 件・見出し右に主ボタン「請求書を作る」あり → 同名のボタンを重ねず、文と文中リンクで導く（決定 9）。条件 0 件は「条件をすべて外す」だけをボタンにし、作る導線は置かない
- E-06：読み込みの失敗は初回 1 種・更新 1 種 → 初回は ErrorState を本体の位置に、更新は一覧の上の警告の知らせ（再試行つき）
- E-07：読むだけ → 見本の取得は手動の「もう一度読み込む」のみ。本物の取得では初回の失敗を自動 2 回、更新の失敗は自動 0 回
- C-02：状況は 5 つ（下書き・送付済み・期限超過・入金済み・取り消し済み）→ 調子は draft・progress・wait・done・calm で `parts/status.ts` のとおり。この画面は足さない
- C-03：期限超過は送付済みで支払期限が今日より前の行 → 計算した札 1 枚。期限前は札を変えず「あと17日」と言葉で足し、超過は「3日超過」と数字で言う
- C-08：見える札は 1 ページ 20 枚（測った）・10 以上 → 見本の 1 ページ目は期限超過 3 枚だけ通常、17 枚は静かな札。`many` の 1 ページ目は 20 枚すべて期限超過（80% 以上）→ 全部静かな札
- C-05：藍の塗りは主ボタン 1 つ → ほかは行のリンクの文字と選択欄の枠の線まで
- C-06：金額・件数の数字は色なし → `fg`、補足は `muted`
- C-07：画面全体の知らせは `stale` のときの 1 つだけ → 色の予算は主ボタン 1・札の調子 5 種・知らせ 0（stale 1）・回る絵 0
- F-03：欄 3・必須 0 → 印は付けない。プレースホルダーは使わず、ラベルが言う
- F-05：探す欄は他人の情報（取引先名）を引くだけ → `autocomplete` なし・`spellcheck` なし
- F-06：探す語の揺れは全角半角・大小・かなの種類・空白・中黒・ハイフン → 欄は書き換えず、照合の側で `lib/foldForSearch` に 1 か所そろえる。空白で区切った語は「かつ」で、照合先は取引先名・かな・請求書番号。変換中は絞らず確定したときに絞る
- G-04：入金待ち 11 件と入金済み・取り消し済みが混ざる → 既定は「入金待ちを先に、支払期限が近い順」（昇順のままでは先頭が過去の入金済み）。列は 取引先→状況→支払期限→税込金額（右端）。いまの並びを件数の行に書く
- G-05：金額は税込で 1 円まで → `Money`（単位は見出し「税込金額（円）」）。¥・万円にしない
- G-07：請求日・支払期限 → 列ごとに `formatDateColumn`（今年以外が 1 件でもあれば全行を長い形）。補足の相対は 14px の `muted`
- G-04：合計は状況が混ざり（取り消し済み・下書きを含む）足した数に意味が無い → 合計は出さない（ホームと売上レポートが担う）
- L-07：初回は「〜はまだありません」＋説明＋導線、条件 0 件は「条件に合う〜はありません」＋外す手段 → 作るボタンは置かない
- L-08：待ちと更新は `app/terms` の messages（更新しています・読み込んでいます・N時点の内容です）→ 画面は引くだけ。画面にしか出ない文は `copy.ts`
- L-12：同じ取引先の請求書が複数 → 行のリンクの読み上げ名に番号を足し、見える文字（取引先名）を含める。チップの外すボタンも見える文字を含める
- S-02：画面の中の小部品（条件の並び・表・欄）は 2 画面以上で使わない → CMP-ID を付けない
- S-03：URL の値・ページ送り・探す語・更新中の文は 5 画面以上で同じ決めごと → 土台（`nav`・`paginate`・`foldForSearch`・`StaleNotice`）を使い、画面に持たない
- S-07：条件・ページは人に見せたい状態 → URL（status・q・sort・page）。件数・ページ数・期限超過かは持たず計算する
- A-05：絞り込み・並べ替え・ページ送りは 1 日に何度も行う → 動かさない。新しい動き 0

## 9. 実装で変えたこと（第 2 段の置き換え。8 件）
- 置き換え（8 件）：URL を読み書きするフック（41 行→ 28 行。`known` の ref・popstate の取り直し・`window.history.replaceState` をやめ、`useRoute` と `replaceParams`）／ページの切り出し（`pageOf`・`PAGE_SIZE` を消し `paginate`）／stale と更新中を `StaleNotice`・`RefreshingNote`／ページ送りを包んでいた `fieldset disabled` をやめ `Pagination disabled`／探す語の正規化（`normalizeForSearch` を消し `foldForSearch`）／many の見本を `data` の `manyInvoices()`／初回 0 件の主と同名のボタンを文中リンクに／`InvoiceTable` は変更なし（`DataTable` が直り、ui-audit の S-01 は不合格 0）。画面の文は `copy.ts`（21 行）へ。消したファイルは 0。画面の行数は 445→ 428（テストを除く）。
- 挙動の変更：初回 0 件は同名のボタンが無くなった。更新中の文は「請求書の一覧を更新しています」から「更新しています。並べ替えとページ送りは、終わるまで変えられません」（止める理由を近くに：E-04）。`filtered_empty` は条件を URL に書いて始める（外すと URL も戻る）。
- 直した不具合：「条件をすべて外す」が quiet だった → 副（枠）にそろえた（D-04）。
- 見つけた穴：期限の補足の言い方を直すとテストも直す必要があった → テストが `copy` を引く形にした（変更シナリオ 2）。
- 土台に足りない物（報告）：条件を入れて始める口（初期値を URL へ入れる）が無く、フックの中で `useLayoutEffect` に 1 回だけ書いた。`useUrlParam` は 1 つの値の読み書きなので、4 つの値を 1 度に検査して書くこの画面は `useRoute`＋`replaceParams` を使った。
