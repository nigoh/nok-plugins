## 1. この画面で人がすること、最初の 1 画面

- 開いて、今日まず片付けること（期限超過の請求書・未確認の入金・下書き）と、今月の 3 つの数字を 1 度に確かめる。行を押すと該当の一覧へ移る
- 新しい請求書を作り始める（主ボタン「請求書を作る」）。請求書が 1 件も無い初回は、作る導線とはじめての設定への入口だけを見る
- 最初の 1 画面（375×812）：見出し → 今日やること 3 行 → 「請求と入金の状況」の見出しと先頭の数字の頭。主ボタンは下に固定。説明文・知らせは置かない

## 3. 判断の記録

- D-01：区画 3 つ、全員が全部読む・見比べる・順番が無い → タブにも畳みにもせず縦に全部並べる
- D-04：主ボタン「請求書を作る」1 つ（別の画面へ行くので LinkButton）。行・リンクは文字のリンク。絵だけのボタン 0 → 「その他」は作らない
- D-06：文字の段 4 つ＝14（補足・札・比べる言葉）／16 太字（区画の見出し・件数）／22（数字 2 つ）／28（今月の請求額 1 つ）。比は 1.14・1.38・1.27 で 1.125 以上。ui-audit が測った段も [14, 16, 22, 28]。12px は使わない → 判断に使う値は 14 以上
- D-07：区画の間 32（スマホ）／48（768px 以上）、見出しと中身 16、数字のかたまりの間 24／32、行の内側の上下 12。刻みに無い余白は 0/162 か所（ui-audit）→ 内側＜仲間＜区画の順を保つ
- D-08：行（今日やること・最近の動き）は地だけ左右 12px はみ出す。件数は右端・右揃え・等幅。数字 3 つは並べるだけで列として比べない → 左揃え。測った左端は 2 本 [16, 24]（24 の出どころは未調査）
- D-09：数字と単位（円・件）・日付は途中で折らない。取引先名は最長 60 字を折り返して全部見せる（many で確かめた）→ nowrap と省略なし
- D-10：税込は数字の見出しに括弧で書く。「最も古い支払期限」は行の 2 行目 → 注記を離して置かない
- D-11：今日やること＝1 行ずつ押す・件数が 3 以下 → 行のリスト。数字 3 つ＝並べるだけ → `dl`。表は作らない
- D-13：数字の最大「99,999,999円」≒ 170px、3 列に要る幅は 3×170＋間 64＝約 600px → 768px 以上で 3 列。1024px 以上は左メニューの残り 800px 弱を「今日やること｜数字」の 2 列、数字は縦 3 つ。375px は 1 列。767/768・1023/1024 の前後で崩れないことをテストで見る
- D-14：画面でいちばん先にすること＝何から手を付けるか → 今日やることを見出しの次に置く。REQ-012「先頭」はこの意味で読んだ
- E-02：状態名は screens.yaml の 6 つのまま。`todo_empty` は画面固有の名前 → 共通の語に足さない
- E-05：0 件は 2 種類で、条件（絞り込み）が無い。初回は説明＋文中リンク、見出し右に主ボタンがあるので 0 件の表示に「請求書を作る」のボタンを重ねない（決定 9）。片付いたは結果を言い、作る導線は出さない → 初回と片付いたを分ける
- E-06：失敗は取得の通信。置き場所は本体の位置（取得が画面全体のため）、role=alert は ErrorState が持つ → 短い知らせは出さない
- E-07：初回の読み込みの失敗は読むだけ。`useFake` の `autoRetry`（自動 2 回）は使える → 挙動が変わるので今回は入れず、手動の「もう一度読み込む」のまま（決める人に報告）
- C-02：期限超過・支払期限を過ぎた未入金・督促を決めるのは人 → wait（手）。未確認の入金も wait。下書き・自分が送る → draft（鉛筆）。調子は足さない
- C-05：藍の塗りは主ボタン 1 個、リンク・現在地・選択は文字か `ai-soft` の地まで → 塗りは 1 か所だけ
- C-06：金額・件数・比率は `fg`、補足は `muted`。売上は増えると良く、未入金は増えると悪い → 増減は塗らず、符号と「比べて」の言葉で言う。矢印は置かない
- C-07：画面全体で人が先にすること＝今日やること（件数つきの行）→ 知らせは default で 0 個。`todo_empty` だけ結果を言う ok の知らせ 1 つ
- C-08：見える札 3 枚（5 枚以下）→ すべて通常の札。`tagDensityOf` に調子を渡して多いとき自動で静かにする
- G-01：値 3 つを並べるだけ、比べる相手は先月の 1 つずつ、時間の点が 4 つ以下 → 図にせず、同じ書式の数字を並べる。大きな数字は 3 つ（上限 3）
- G-03：期限超過の件数は基準（支払期限）がある数字だが、同じ画面の先頭の行に札つきで出ている → 数字の隣に札を足さない（同じ警告を 2 回出さない）。未入金の額は件数と最も古い期限を隣に書く
- G-05：金額は全桁・円は数字の直後・1 円まで丸めない、差は 0 以外に「+」、負は U+2212 → 整形は `lib/format` の関数だけで、画面に書かない
- G-07：期限は絶対の日付（10/31(土)）が主、相対（13日超過）は補足。履歴は 24 時間未満が「N時間前」、以上は「11/12(木) 15:20」。同じ列に今年以外が 1 件でもあれば全行を長い形 → `formatDateColumn`・`formatAgo` を引く
- L-04：区画の見出し 3 つはどれも 16 字以内の名詞で、句点なし → 「今日やること」「請求と入金の状況」「最近の動き」
- L-07：初回の説明は 1 文（何をすればここに並ぶか）、次の一手は文中リンク → 主ボタンを重ねない。「まだ」は初回だけ
- L-08：骨組みの読み上げは最初の 1 つだけ、残りの骨組みは隠す（同じ文を 3 度言わせない）→ 画面に 1 つの `role=status`
- L-13：画面にしか出ない文はこの画面の `copy.ts` 1 か所。画面名・ボタンの動詞は terms から引く → 直書き 0
- S-02：行・区画は 1 画面だけで使う → 画面のフォルダに置き、CMP-ID は付けない
- S-07：画面の状態は `?state=` の列挙 1 つ、取得の結果は `Fake<HomeData>`。件数・合計・先月との差は計算できる → 持たず描くたびに `summary.ts` で計算する。URL に持つ物は 0（絞り込み・ページ・タブが無い）
- A-05：1 日に何度も開く画面 → 数字・区画・片付いた知らせ・loading から本体への入れ替えは動かさない

## 7. 構造の設計図

- 部品の木：
  `ホーム（画面）　取るデータ：useFake(state, homeSample)。URL：state だけ`
  `├ HomeBody（画面内）　3 区画の並び、1024px 以上で 2 列の格子`
  `│ ├ TodoSection → TodoRow（行全体が 1 つのリンク。札は InvoiceStatusTag・PaymentStatusTag）`
  `│ ├ MetricsSection → Metric（dl の 1 組。Money）`
  `│ └ ActivitySection → ActivityRow（行全体が 1 つのリンク）`
  `├ HomeSkeleton・ErrorState・EmptyState（loading・error・empty）`
  `└ summary.ts（純粋な計算）／sampleVariants.ts（todo_empty・many の見本）／copy.ts（文言）`
- S-01：行（`a`）の中は `span`・札・絵だけ。ボタン・別のリンクを入れない。`ul > li > a`、数字は `dl > div > dt + dd`、区画は `section`＋`h2`
- S-10：見た目の順＝DOM の順（今日やること → 数字 → 動き）。2 列は格子の自動配置で `order` を使わない。同じ id は 3 つの見出しだけ

## 8. 動きの仕様

新しい動き 0。基本の部品が持つ応答だけ。

## 9. 実装で変えたこと

- 置き換え 0 件。置き換え表の 1 件は「`makeManyInvoices(240)` を `filter` して使う」ので変えない判断（`manyInvoices()` は共有の物で、home は請求日が今日より先の物を外すため使わない）
- 画面の文言を `copy.ts` に集めた（tsx 8 ファイルの直書き約 25 か所。ファイル名の番人は home に違反が無かった）。見た目・挙動は変えない
- 最近の動きの上限を `summary.ts` の `ACTIVITY_LIMIT` に 1 つにした（変更シナリオ 1 で穴が出た：骨組みの 5 行・テストの 5 が別々だった）
- 下に固定した帯が最後の要素を隠す件は土台で直った。ui-audit の `fixed-band-last-item` は 6 状態で合格
- `save_failed` は home の states に無く（保存が無い）、足していない
- 足りなかった物（土台）：`useFake` の `autoRetry` は使えるが、使うと挙動が変わる（初回の失敗が自動で 2 回やり直される）ので、決める人の判断を待つ
