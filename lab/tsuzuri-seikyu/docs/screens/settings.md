## 1. この画面で人がすること

自社の情報・請求書の番号と税の端数・通知を、区分（3 つ）を切り替えて直し、「保存する」で確定する。

最初の 1 画面（375×812）に置く物（D-14）：見出し「設定」→ 区分の切り替え 3 つ → 自社の情報の先頭の欄（会社名・郵便番号・住所）。主ボタン「保存する」は下に固定（骨格）。説明文は置かない（区分の名前と欄のラベルで足りる）。食い違い（conflict）のときだけ、人が選ぶ必要があるので知らせを先頭に置く。

## 2. 判断の記録

### 切り替え・入力・操作・並び・文字・余白（D-）
- D-01：区分 3 つ・同格・最長 7 字・同時に見るのは 1 つ・見比べない・375px で 3 つ合わせて 244px（<343px）→ タブ（折り返さない）。選んだ区分は URL の `tab` に持ち、切り替えは履歴に積まない（REQ-027、`replaceState`）。F-01 の「項目 9〜20・塊 3 つ以内 → 1 画面に節」とは食い違うが、REQ-025「区分で切り替えて直せる」を優先した（報告）。
- D-02：税の端数処理・3 択・最長 4 字・保存で確定・結果の違いを見比べたい → セグメント。Select（6〜15 個）にしない。例は補足文に 3 つ並べて見せる（P-1）。
- D-02：通知の場面・3 個・各 2 択・保存で確定 → チェック（スイッチにしない）。REQ-025 は「通知（スイッチ）」と書くが、D-02「保存で確定する 2 択はスイッチにしない」と I-23「即時反映と保存ボタンを混ぜない」を優先した（報告）。
- D-03：数値の入力欄は無い（番号の頭は文字列）。
- D-04：主ボタン「保存する」1 つ（藍の塗り）。副の操作は置かない（取り消し・離れるは骨格のメニューと窓が受ける）。食い違いの 2 つの選びは主にしない（ふつうのボタン）。保存中以外に取り返しのつかない操作は無い。
- D-05：保存するは 1 個・5 字 → 768px 以上は末尾の右、未満は下に固定（骨格、F-10）。
- D-05：食い違いの選び・2 個・最長 9 字・375px で 2 個合わせて 254px（<343px）→ 常に横。順は「相手の内容を使う」→「上書きして保存する」（安全な側が先）。
- D-05：離れる窓・3 個・最長 7 字 → 768px 以上は 1 行に右寄せ（350px < 窓の内側 464px）、未満は縦に積み主が下（窓の決まり）。順は「やめる」→「保存せず離れる」→「保存して離れる」。
- D-06：段は 3 つだけ（見出し 22 太字・入力欄 16・本文と補足 14）。補足文は入力に要る規則なので 12px にしない。新しい大きさを作らない。
- D-07：欄どうし 24px（gap-6）、区分と中身の間 24px、窓の中 16px。刻みの段だけ。
- D-08：左端は 1 本（ラベル・欄・補足が同じ線）。食い違いの表は文字だけで数の列が無いので左揃え。
- D-09：数字と単位・番号の例は折らない（`whitespace-nowrap`）。住所・振込先は欄の中で折り返して全部見せる（Textarea）。
- D-10：番号の注意（送付済みは変わらない）は番号の頭の補足に常時、さらに保存の直前（番号を変えるとき）の窓にも書く。未保存の表示と保存の失敗は末尾（操作の直前）。食い違いは先頭（人が選ぶ必要がある：D-14）で、選ぶボタンを知らせのすぐ下に置く。
- D-11：食い違いの項目は 3 つの軸（項目・自分の内容・相手の内容）で見比べる → 表（DataTable。枠 672px 未満は行に組み替わる）。
- D-12：図は作らない（G-01：端数の例は 3 点の数字で足りる）。
- D-13：組み替えが起きるのは表（枠 672px。部品が持つ）と、骨格の主操作（768px）だけ。この画面は新しい境目を作らない。
- D-14：上の「1.」のとおり。

### 状態（E-）
- E-01：5 軸を見直した（下の状態表）。足りない状態は無い。要らない状態も無い。ただし「保存の失敗（通信）」を表す名前が無く、`?state=` で再現できない。`error` は設定を読み込めないとき専用のまま、保存の失敗は default の上の知らせで扱い、テストでは保存を差し替えて確かめた（報告）。
- E-04：`saving` は欄を変更不可（fieldset の disabled）にし、押したボタンだけ処理中にする。`loading` と `error` は見出しと主ボタンの位置を残し、主ボタンは押せなくする（理由は隣の「読み込んでいます」「読み込めませんでした」）。
- E-05：0 件の画面ではない（自社の情報は必ず 1 件）ので empty・filtered_empty は無い。
- E-06：保存の通信の失敗は末尾の知らせ（role=alert）。窓の中の保存は窓の中に出す（窓は閉じない）。入力は消さない。
- E-07：保存は書き込みなので自動で再試行しない。手動で「保存する」を押し直す。
- E-08：番号の付け方を変えない保存は、戻せる・相手に届かない・お金に関わらない → 窓なし、済んだ知らせに「元に戻す」（10 秒）。番号の付け方を変える保存は、番号に関わる → 窓で確かめ、確定後に「元に戻す」。
- E-09：食い違いは `conflict`。「別の人が HH:MM に更新しました」、変えた項目が重なった物だけを表に並べる。重ならない物は黙って取り込み「ほかの人の更新も含めて保存しました」。相手の内容を使うときは自分の入力を控えに残す。保存する間の連打は 1 回だけ（`saving` の ref）。

### 色と状況（C-）
- C-05：藍の塗りは「保存する」だけ。区分の選択中は下線と太字、端数処理の選択は ai-soft の地と細い線（部品のまま）。
- C-06：数字（端数の例）に色を付けない（fg）。食い違いの値も fg。色は知らせだけ（warn：食い違い、fail：保存の失敗、info：控えを残した）。
- C-07：知らせは同時に 2 つまで（食い違い＋控えは同時に出ない。保存の失敗＋誤りの一覧は同時に出ない）。
- C-09：押せない「保存する」（loading・error・conflict）は理由を隣の文で言う。conflict は `aria-describedby` で知らせに結ぶ。
- 色の予算：`SCR-009 設定：主ボタン 1・藍の塗り 1・札の調子 0 種（札は使わない）・知らせ 最大 1〜2・数字の色すべて fg・回る絵 0（保存中の印はボタンの中の 1 つ）`

### 入力（F-）

- F-04 確かめ：形式は欄を離れた時（空欄は出さない）、空欄の必須は保存する時、2 件以上で先頭に一覧（リンクは欄へ。別の区分の欄なら区分を切り替えてから移る）。入力中は出さない。直した瞬間に消す。最初の誤り欄へフォーカス（誤りのある最初の区分へ移ってから）。
- F-05：自社の情報は本人（事業者）の情報なので autocomplete を付ける。登録番号・振込先・番号の頭は付けない。金額の欄は無い。
- F-06：郵便番号・電話・登録番号は、全角・ハイフンの種類・空白を受け、離れた時に半角へ直し、欄の補足を「半角にそろえました。」に替える（直した時だけ）。登録番号は大文字にそろえ、ハイフンと空白を除く。番号の頭は全角の英数字を半角に直す。意味が変わる直し（半角カナなど）はしない。
- F-07：初期値は保存済みの値。人が直した欄を自動で書き換える物は無い。番号の例だけが入力に合わせて変わる（欄ではなく補足文）。
- F-09：下書きの状態が無い・入力 3 分以内 → 自動保存しない。未保存の変更があると末尾に「未保存の変更があります」を出す。画面を離れる（メニュー・戻りのリンク）と窓で「保存して離れる」（主）「保存せず離れる」「やめる」。変更が無いとき・保存済みのときは出さない。ブラウザの更新・閉じるは標準の確かめ（beforeunload）。ブラウザの「戻る」は止められない（報告）。
- F-10：「保存する」は末尾の右（768px 以上）、768px 未満は下に固定。必須が空でも押せる（押すと誤りを出す）。保存中は押したボタンだけ処理中（「保存しています」）、欄は変更不可。成功はこの画面に残り、短い知らせ「設定を保存しました」（結果がこの画面で見えるので移動しない：W-06 の例外を設計書に記す）。失敗は入力を残して末尾の知らせ。
- F-11：新規と編集の区別は無い（設定は常に編集）。

### 入れ子と順序の確認（S-01・S-10）
- 押せるものの中に押せるものを置かない：Notice の中にボタンを入れるのは Notice の `action`（兄弟）だけ。表（DataTable）は Notice の外に置く。Checkbox は label の中に input 1 つ。
- 一覧・表の構造：DataTable が role を持つ。Dialog の番号の例は `dl > div > dt + dd`。
- 見た目の順と DOM の順は同じ：入力画面の主ボタンは末尾（AppShell が末尾に置く）。食い違いの知らせは DOM でも先頭。`order-*` と `flex-*-reverse` は使わない。
- 見出し：h1（骨格）→ 各区分の h2（読み上げ専用で `sr-only`）。タブの中身は `role=tabpanel` を 1 つだけ。
- 入力欄の id は fields.ts で一意（`settings-…`）。まとめの一覧のリンク先と一致する。
- `div onClick` は作らない。リンクの押下は document の capture で拾う（useLeaveGuard）。

### 状態の持ち場所（S-07）
- 画面の状態は `?state=` の列挙。取得の結果は `Fake<…>`。
- 区分（tab）は URL。画面の中に写しを持ち、変わったら URL を `replaceState` で直す（初期値だけ URL から読む）。
- 入力中の値・誤り・控えは画面の中（useSettingsForm）。保存済みの値は保存が成功したときだけ更新する。
- 未保存かどうか（dirty）・番号を変えたか・必須の数は持たず計算する。
- 窓は 1 つの列挙 `dialog: null | numbering | leave`（真偽値を並べない）。保存中・失敗・食い違いは別の軸なので別々に持つ。

## 6. 実装で変えたこと
- 区分と欄の定義を `model.ts` から `fields.ts` に集めた（TABS・FIELDS・ROUNDING_OPTIONS・NOTIFY_OPTIONS）。型 TabId は TABS から引く。上の変更シナリオの 4・5・6・7 は、この形で数え直した。
- 保存の流れを `useSaveFlow.ts`、入力の流れを `useSettingsForm.ts`、離れる確かめを `useLeaveGuard.ts` に分けた。窓は `NumberingDialog.tsx`・`LeaveDialog.tsx`、食い違いは `ConflictPanel.tsx`・`BackupNotice.tsx`。
- 欄を離れた時は、空の欄の誤りを消さない・出さない（保存した直後の「空の必須」の誤りが、一覧のリンクを押す瞬間に消えてしまったため）。空は保存する時だけ見る。
- 誤りの一覧のリンクが別の区分の欄を指すとき、区分を移してから欄へフォーカスする（フォームで押しを受け取る）。
- 端数処理の説明は、Segmented が説明の結び付け（aria-describedby）を受けないので、Field の補足として見える所に出すだけにした（読み上げへの結び付けは土台の不足）。
- 保存の失敗・食い違いは、見本の状態名に無いので、`SettingsFrame` に保存の関数（Saver）を渡せる形にして試験で出す。
