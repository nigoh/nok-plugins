# SCR-007 入金の確認（slug: payments）の設計書

covers：REQ-001, 002, 003, 007, 008, 021, 022, 027。kind は view（主操作は 768px 以上で見出しの右、未満は下に固定）。
states（screens.yaml と同じ並び）：default, loading, error, empty, many, candidates_empty, status_diff, confirming, partial, saving, refreshing, stale。

## 1. この画面で人がすること、最初の 1 画面に置く物（D-14）

- 銀行に入った入金（通帳の振込名義と金額）を、請求書と突き合わせて確認する。名義と金額が合う請求書が 1 つに決まる入金はまとめて確認し、それ以外は候補から選ぶか、請求書を探して選ぶ。金額が違うときは、差額と理由を見て「手数料として確認する」か「確認せず戻る」を選ぶ。
- 最初の 1 画面（375px・高さ 812px 目安）：見出し → 「未確認の入金」の見出しと件数・合計・いちばん古い入金 → 未確認の入金の表の先頭の数行。主ボタン「まとめて確認する」は下に固定。説明文は置かない（見出しと「未確認の入金」で何の画面か分かる。D-14：題名→説明→知らせ→本体の定型にしない）。
- 知らせ（更新できなかった・一部確認できなかった）は、人が先にすることがあるときだけ表の上に置く。

## 2. 判断の記録

### 2.1 部品・並び・文字・余白（D-）

- D-01：未確認と確認済みを切り替えるか → 見比べはしないが、確認した入金が「確認済み」へ移ったことを同じ画面で見たい（移ったことが見えないと、確認できたか分からない）。確認済みは 6 件で、お金に関わる結果なので畳まない。切り替え（タブ・畳む）にせず、2 つの区画を縦に並べる。
- D-02：候補の請求書（1〜3 件。探した結果は最大 5 件）から 1 つ選ぶ・すぐ反映せず「入金を確認する」で確定 → ラジオ（縦）。土台に Radio が無いので、自分のフォルダに CandidateOption を置く（報告済み）。まとめて確認する対象は、確定の操作で決まる複数選択 → チェック（Checkbox）。スイッチにしない。
- D-03：金額を入れる欄は無い（差額は計算結果）。数値入力・スライダーは使わない。
- D-04：主ボタンは「まとめて確認する」の 1 つ（見出しの右・藍の塗り）。行の「入金を確認する」「請求書を選ぶ」「差額を確かめる」と、パネルの確定は、ふつうのボタン（枠）。別画面へ行くのはリンク（請求書番号 → 請求書の詳細、片付いたあと → ホーム）。戻せない操作は無い（確認は「元に戻す」で戻せる）ので danger は使わない。
- D-05（パネルの 2 択）：ボタン 2 個・最長 13 字（「差額を手数料として確認する」）・375px で 1 行に収まらない（(375−32−8)÷2＝167px、内側の左右を引くと約 135px。14px×13 字＝182px）→ 縦に積む。パネルは「選んで確定する」入力の末尾と同じ働きなので「やめる→主」の順で主が下（DOM も同じ）。768px 以上は横に並べ、右寄せ。
- D-05（窓）：Dialog の secondary（やめる）と primary（入金を確認する）に渡す。順は土台が決める。
- D-05（ヘッダ・下に固定）：AppShell の primary に渡す。副は無い。
- D-06：文字は本文 14px（text-body）、区画の見出し 16px 太字（text-large）、画面の見出し 22px は骨格。段は 3 つ（比 1.14・1.375。1.125 以上）。補足（件数・候補・理由）も 14px の muted。12px は使わない（判断に使う値だから）。
- D-07：区画の間は骨格の gap（スマホ 32px、md 以上 48px）。区画の中は「見出しと要約 8px（gap-2）→ 要約と本体 16px（gap-4）」。パネルの内側は Card の余白（スマホ 16px・PC 24px）、パネルの中の仲間どうしは 16px、候補の 1 つの内側は 12px。同じ階層の繰り返し（表の行・候補）は全部同じ余白。刻みは 1・2・3・4・6・8・12 の段だけ。
- D-08：名義の列は、チェックのある行とない行が混ざる → ない行は 48px（チェックの箱 44px＋間 4px）空けて文字の頭を揃える。数の列（金額）は右揃え・等幅・単位は見出しの「金額（円）」へ。左端の線は 2 本（区画の左端、名義の文字の頭）。
- D-09：名義・取引先名（最長 60 字）は折り返して全部見せる。日付・金額・「円」は途中で折らない（nowrap、Money と formatDateShort）。ボタンの文言は折り返さず、表の中の操作列は文言が収まる幅（lg）。見出しは text-wrap: balance（既定）。
- D-10：押せない理由は押せないボタンのすぐ近く（「選んでいます」の状況の文、更新中の文）に置く。差額の理由と 2 択は、選んだ候補のすぐ下（離れた注記にしない）。
- D-11：未確認も確認済みも「日付・金額・状況を見比べる」ので表（DataTable）。狭い幅は行に組み替わる。パネルの候補は 1 件ずつ読むので縦のラジオの並び。
- D-12：図は無い（G-01：値が少なく形が主役でない。件数と合計は文で言う）。
- D-13：表の境目は土台どおり枠 672px。未確認の表の列幅の合計は 名義 fill＋入金日 96＋金額 96＋状況 96＋操作 192＝480＋間 64＋内側 32＝576px で、枠 704px（viewport 768px）の名義は約 128px → 名義が 3 行まで折れる（D-09 のとおり全部見せる。崩れない）。1280px の枠は約 992px で名義は 400px 以上。境目を列の数で変えたい → 報告。
- D-14：1 節のとおり。

## 4. 構造の設計図

### 4.1 部品の木


知っていること（S-04）：画面＝どのデータが要るか・URL と状態の対応。useReconcile＝確認の操作の結果と選択の持ち場所。MatchPanel／DiffChoice／CandidateOption／表＝受け取った値を並べるだけで、取得も確定も知らない（確定は onConfirm で親へ）。logic.ts＝業務の計算だけで、見た目を知らない。受け取るもの（S-09）は各ファイルの Props に集める（真偽値の切り替えは `locked` 1 つ）。

### 4.2 入れ子と順序の確認（S-01・S-10）

- 表のセルの中に Checkbox（label＋input）・Button・Link を置くが、押せるものの中に押せるものは無い（Checkbox の label の中に Button を入れない。候補の文は label の外の `p`）。
- CandidateOption は label の中に input と span だけ（リンクやボタンを入れない）。候補の一覧は fieldset と legend。
- 表は DataTable（role を土台が付ける）。窓の内訳は `ul > li`。
- 見た目の順＝DOM の順：パネルのボタンは「やめる→主」。order・flex-reverse は使わない。パネルは表の前（DOM でも前）に置く。
- 見出し：h1（骨格）→ h2（未確認の入金／確認済みの入金／入金の突き合わせ）。パネルは未確認の区画の中なので h3 にする。
- パネルを開いたらパネルの見出しへフォーカスを移す（開いた所を見失わない）。閉じたら未確認の見出しへ戻す。

### 4.3 状態の持ち場所（S-07）

- 画面の状態：`?state=` の列挙 1 つ。取得の結果は Fake<T>。開いた入金は URL（`?pay=`）、ページは URL（`?page=`）。どちらも履歴に積まず置き換える（REQ-027）。
- 画面の中：確認した入金（入金 id→請求書 id）、チェックを外した入金（初期は 1 つに決まる入金をすべて選ぶ＝外した物だけ持つ）、選んだ請求書、探す語、窓の開閉、処理中の相手、一部失敗の結果。
- 計算して持たない物：状況（入金と請求書から）、候補、差額、件数・合計、選べるか。

## 6. 実装で変えたこと

設計の項目は消さず、実装で動かして変わった所だけをここに足す。

- 状態の初期の置き方：状態名で最初に開いておく入金（status_diff は pay-008、candidates_empty は pay-007）を、`?pay=` が無いときだけ URL に置く。設計では「開いた入金は URL」としか書いていなかった。
- saving は、確認の処理を始めた直後の姿のまま止める（窓は閉じられず、確認のボタンは処理中）。終わりを待つ状態ではなく、処理中の見え方を確かめる状態として扱う。
- 更新中・古い内容のとき、行の「請求書を選ぶ」（パネルを開く）は押せるままにした。見るだけで確定しないため。確定する操作（直接の確認・まとめて確認・パネルの確認）だけを止め、止める理由は aria-describedby で結ぶ。
- 一部失敗の理由は、設計の「別の人が先に入金済みにした」ではなく「通信が途中で切れました。」にした。見本のデータでは請求書は未入金のまま残り、再試行が成り立つのは通信の失敗だから。
- 表の件数：確認済みの表は新しい 10 件までとし、超えるときは「新しい10件を表示しています」を添える（設計の「確認済みは多くならない」を、many で 6 件超になっても崩れないように補った）。
- 差額の「差額を手数料として確認する」は 13 字のまま（REQ-022 の名前）。L-03 の 9 字を超えるので、要確認として残す。
