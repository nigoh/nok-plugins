## 1. この画面で人がすること、最初の 1 画面
- 自社の情報・請求書の番号と税の端数・通知を、区分（3 つ）を切り替えて直し、「保存する」で確定する。
- 同時に直されていたら、同じ項目だけ見比べて選ぶ。未保存のまま画面を離れるときは、骨格の窓で確かめる。
- 最初の 1 画面（375×812）：見出し → 区分 3 つ → 自社の情報の先頭の欄（会社名・郵便番号・住所）。主ボタンは下に固定。`conflict` のときだけ食い違いの知らせを先頭に置く。

## 3. 判断の記録
- D-01：区分 3 つ・同格・最長 7 字・同時に見るのは 1 つ・375px で 3 つ合わせて 244px（＜343px）→ タブ（折り返さない）。URL の `tab` に持ち、既定の「自社の情報」は書かず、履歴に積まない（REQ-027）。
- D-02：税の端数・3 択・最長 4 字・保存で確定・結果の違いを見比べたい → セグメント。通知の場面・3 個・各 2 択・保存で確定 → チェック（スイッチにしない）。REQ-025 の「スイッチ」は見た目の指定なので理論を正に（要件の直しは報告）。
- D-04：主ボタンは「保存する」1 つ。副の操作・離れる・取り消しは骨格が受ける → 副は置かない。食い違いの 2 択は主にしない（ふつうのボタン）。
- D-05：食い違いの選び・2 個・最長 9 字・375px で 2 個合わせて ≈254px（＜343px）→ 常に横。順は「相手の内容を使う」→「上書きして保存する」（安全な側が先）。
- D-06：文字の段が 3 つ［14・16・22］（ui-audit で測定）・補足文は入力に要る規則 → 12px にせず段を増やさない。
- D-08：ラベル・欄・補足が同じ左端 1 本（ui-audit：左端の線 1 本［16］）→ 食い違いの表も左揃え。
- D-09：住所・振込先は長くなる → 欄の中で折り返して全部見せる（Textarea 3 行）。番号の例・数字と単位は折らない。
- D-10：番号を変えても送付済みは変わらない → 番号の頭の補足に常時、窓にも書く。未保存の表示・保存の失敗は末尾（操作の直前）、食い違いは先頭。
- D-11：食い違いの項目・3 軸（項目・自分・相手）で見比べる・最大 12 行 → 表（DataTable）。
- E-04：`saving` は保存中に欄と区分を触れると値が割れる → 欄・区分・チェック・セグメントを `disabled`（`fieldset` で代用しない）、押したボタンだけ処理中。`loading`・`error` は見出しと主ボタンの位置を残し、押せない理由は隣の文。
- E-06：保存の通信の失敗は保存の近く → 末尾の fail の知らせ（`role=alert`・「保存できませんでした。入力は残っています。もう一度保存してください。」）。入力は消さない。
- E-07：保存は書き込み → 自動で再試行せず手動のみ。
- E-08：番号の付け方を変える保存は番号が付く → 窓で確かめ、確定後に「元に戻す」。変えない保存は戻せる → 窓なし、済んだ知らせに「元に戻す」。
- E-09：同じ項目を両方が違う値にした（例：電話）→ `conflict`、表に並べて選ばせる。重ならない更新は黙って取り込み「ほかの人の更新も含めて保存しました」。相手の内容を使うときは自分の入力を控えに残す。連打は 1 回だけ。
- C-05：藍の塗りは主ボタン 1 つ → 区分の選択は下線と太字、端数の選択は `ai-soft` の地と細い線（部品のまま）。
- C-06：端数の例・食い違いの値の数字 → `fg`。色は知らせだけ（warn：食い違い、fail：保存の失敗、info：控え）。知らせは同時に 2 つまで。
- C-09：押せない「保存する」（`loading`・`error`・`conflict`）→ 薄くして理由を隣の文で言う（`conflict` は `aria-describedby` で結ぶ）。
- F-01：項目 8（文字の欄）＋端数・通知・塊 3 → 1 画面に節が通常だが、REQ-025 が「区分で切り替えて直せる」と決めている → タブ（要件を正にした例外、REQ-025）。
- F-03：必須 4・全体 8（必須が半分以下でない・任意が半分）→ 任意の欄に「任意」、必須に印なし。端数・通知は空にならないので数えない。補足は常時、プレースホルダーは使わない。
- F-04：形式は離れた時、空の必須は保存する時（Tab で通っただけで叱らない）、2 件以上で先頭に一覧（リンクは欄へ。別の区分の欄なら区分を移してから）→ 入力中は出さず、直した瞬間に消す。
- F-05：自社の情報は本人の情報 → `autocomplete` を付ける。登録番号・振込先・番号の頭は付けない。
- F-06：全角・ハイフンの種類・空白 → 離れた時に半角へ直し、直したときだけ補足に「半角にそろえました」（土台の `wasWidened`）。登録番号は大文字にそろえ `-` を除く。意味が変わる直し（半角カナなど）はしない。
- F-09：下書きの状態が無い・3 分以内の入力 → 自動保存しない。未保存を末尾に出し、離れるとき骨格の窓（順は 保存せず離れる→入力に戻る→保存して離れる（主））。変更が無い・保存中は出さない。
- F-10：入力画面 → 「保存する」は末尾の右（768px 以上）、未満は下に固定。必須が空でも押せる（押すと誤り）。成功はこの画面に残り知らせる（結果がここで見える：W-06 の例外）。
- L-05：離れる窓の言い方 → 骨格の `messages.leave`・`actions`（画面は持たない）。番号の窓は題と主を同じ動詞に（「変えますか」→「付け方を変える」）。
- L-06：保存の失敗・読み込みの失敗 → 「何が＋残っている＋次」（terms と copy.ts）。欄の誤りは空が指示、形式が事実＋頼み。

## 9. 実装で変えたこと（第 2 段の置き換え 7 件）
- 離れる窓：自作の `useLeaveGuard.ts`（42 行）・`LeaveDialog.tsx`（26 行）を消し、AppShell の `dirty` と `onSaveBeforeLeave`。窓の並びと言い方を、全画面で同じ 離れる→入力に戻る→保存して離れる（主）に（旧は「やめる」→離れる→保存して離れる。決定 9）。番号の頭が変わっていると、「保存して離れる」は離れず番号の窓を出す（確かめを飛ばさない。離れ直しは 1 回）。
- 文字の欄：自作の `TextField.tsx`（36 行）を消し、ui の `TextField`。`form.fieldProps(key)` が定義から値を渡す。知らせは補足の末尾に続ける（旧は補足と入れ替え。「半角にそろえました。」の句点を取った）。
- 区分：`useUrlParam('tab')`（自作の replaceState をやめた）。保存中は `Tabs`・欄・セグメント・チェックを `disabled`（`fieldset` をやめた）。
- 入力の読み：`toHalf`・`toHalfDigits`・`wasWidened`。長音「ー」だけを「-」に直した場合は知らせない（旧は言った）。
- 保存：`fakeSave`（待ち 700 → 600ms）。失敗は値で受ける。`saverFor` が `Saver` に包む。`conflict` の状態では上書きの保存を成功させる（土台の `outcomeOf('conflict')` は上書きを見ないので使わない）。
- 文言：`words.ts`（50 行）を `copy.ts`（39 行）に。保存しています・保存できませんでした・離れる窓・相手の内容を使う・上書きして保存するは terms から。
- `save_failed` を足した（`?state=save_failed`）。行数（テスト除く）910 → 809（消したファイル 3＝104 行）。
- 土台に足りない物：骨格の離れる窓は同じ画面かを URL の完全一致で見るので、`?tab=invoice` の上でメニューの「設定」を押しても窓が出る。
