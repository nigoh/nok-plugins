## 1. この画面で人がすること、最初の 1 画面
- 初めて使う人が、3 段（自社の情報 → 請求の決まり → 最初の取引先）を順に入れて設定を終え、ホームへ行く。途中でやめても、次に開くと続きの段から始まる（REQ-026）。
- 最初の 1 画面（375×812）：戻り → 見出し → 説明 1 文 → 手順（全3段のうち1段目）→ 段の見出しと導入文 → 会社名の欄。下に固定の「やめる」と「次へ進む」。主役は 1 段目の入力。

## 3. 判断の記録
- D-01：段 3 つ・同格・順に進む → 手順の表示（Stepper）。タブにしない（途中の段へ飛べない）
- D-02：税の端数 3 個・税率 2 個 → セグメント。支払条件 6 個 → セレクト
- D-04：押せる操作が段ごとに 2〜3（進む・戻る・やめる・あとで登録）→ 主は 1 つ（次へ進む／設定を終える）。「あとで登録する」は quiet、「やめる」は移動なのでリンクの形
- D-05：下に固定の帯・2 個・最長 7 字（前の段へ戻る）・7 字×14px＝98px＋余白 32px＝130px ＜ 1 個 167px（375px）→ 横 2 つ
- D-10：「いま登録しなくても、設定を終えられます。」は「あとで登録する」の直前に置く → 押す操作の上に注意を置く
- D-14：最初の 1 画面に入る主役 = 1 段目の入力 → 手順は見出しの次。説明は 1 文。続きのときだけ先頭に知らせ（出す事実があるとき）
- C-05：藍の塗りは主ボタン 1 つ → 手順の現在地は線と文字（「いま。全3段のうち1段目」）まで
- C-10：誤りの文字 = `bad-text`＋絵＋文＋枠 → 色だけにせず 4.5:1 は土台の色の対（ui-audit axe-serious 0 件）
- E-02：最後の保存の失敗 → `save_failed`（読み込みの失敗 `error` とは別）。段の名前 → `step_2`・`step_3`。続き → `resumed`
- E-06：保存の失敗 → 主の直上の Notice（role=alert）、入力は残す。読み込みの失敗 → 本体の位置の ErrorState
- E-07：保存（書き込み）→ 自動で繰り返さず、押し直しだけ。読み込みの失敗 → 「もう一度読み込む」
- E-08：最初からやり直す = 入力が消えるが戻せる・届かない・お金に関わらない → 窓にせず「元に戻す」（Toast）
- E-09：連打 → 押した瞬間から押したボタンだけ処理中、1 回だけ効く。保存中は欄を変えられない
- E-10：段 3 つ・途中でやめる前提（REQ-026）→ 欄を直すたびに保存。次に開いたら続きの段から（`resumed`）。終わったら `done`→ホーム
- F-01：項目 14（6＋5＋3）・塊 3 で 1 画面に節でも収まる数だが、REQ-026 が途中でやめる前提 → 段階 3 つ。現在地と全体数を出す
- F-03：1 段目は欄 6・必須 4＝半分より多い → 任意の 2 欄に「任意」。2 段目は欄 5・全部必須 → 印なし、先頭に「すべて入力してください。」。3 段目は欄 3・必須 2 → 任意の 1 欄に「任意」。印は `markFor(必須か, fieldCount(段))`
- F-04：形式の誤り（郵便番号・電話・メール・登録番号）→ 離れた時に欄の直下。空の必須は送る時だけ。2 件以上で先頭に一覧（フォーカスは移さない）、1 件は一覧なし。最初の誤り欄へ移る
- F-05：1 段目は自社の情報 → autocomplete を付ける。3 段目は取引先の情報 → 付けない。郵便番号 numeric、電話 tel、メール email
- F-06：全角・ハイフンの種類 → 離れた時に `toHalf`・`toHalfDigits` で直す。前後の空白を除いただけ → 「半角にそろえました」を言わない（`wasWidened`）。欄ごとの規則（郵便番号 7 桁・登録番号の T と 13 桁・番号の頭）は欄の表に置く
- F-07：2 段目の初期値（番号の頭 INV-・切り捨て・10%・月末締め・翌月末払い）= 多くの事業者の決まり → 初期値を入れる。「あとで設定から変えられます」と導入文に書く
- F-09：段ごとに保存し続ける・途中でやめる前提（REQ-026）→ 離れる窓は持たない（`dirty` を渡さない）
- F-10：主は入力の末尾の右（768px 以上）、未満は下に固定。順はやめる→主。必須が空でも押せる。3 段目の成功はホームへ移り知らせる
- L-03：主 4〜6 字（次へ進む・設定を終える）、副 7 字（前の段へ戻る）→ 全画面の語は `actions` から引く。処理中の主は 7 字（保存しています）
- L-13：画面にしか出ない文 → `copy.ts`。次へ進む・前の段へ戻る・保存しています・半角にそろえました・保存の失敗は `app/terms` から引く。欄の補足と誤りの文は欄の表（`model.ts`）に置く（欄と文を別ファイルに割らない）

## 7. 構造の設計図
部品の木（画面の中だけの小部品に CMP-ID は付けない）：
```
Setup（画面）取るデータ：保存した入力（useFake）。URL：?state=（段と状態）
├ useSetupFlow（値・誤り・保存の局面・段の移動）。段は持たず ?state= から決める
├ DoneView／Skeleton・ErrorState（基本）
└ <form> → StepPanel（見出し h2・導入文）→ CompanyStep／RulesStep／ClientStep → StepField → TextField（基本）
model.ts（段・欄の表・初期値・検査）／draft.ts（入力の保存先）／copy.ts
```
| 持つ物 | 置き場所 | 理由 |
| --- | --- | --- |
| 段・状態 | `?state=`（`step_2`・`step_3`・`resumed` ほか） | 戻る・再読み込みで同じ段（REQ-027） |
| 入力値・誤り・知らせ | `useSetupFlow`（値は欄を直すたびに `draft.ts` へ保存） | 途中でやめても続き（REQ-026） |

| 個人情報 | URL に入れない | REQ-027 |

## 9. 実装で変えたこと
- 今回の置き換え 5 件：①`TextField.tsx` 41 行 → `ui` の `TextField`（段の欄の数は `markFor(必須か, fieldCount(段))`。薄い呼び出し `StepField` を `StepPanel.tsx` に 23 行置き、読み上げ用の status 1 行は画面に残す）。②`saveSetup.ts` 8 行 → `fakeSave`＋`outcomeOf(state)`（失敗は値で受ける）。③`model.ts` の `half`・`needsNote` → `toHalf`・`toHalfDigits`・`wasWidened`。④`copy.ts` の次へ進む・前の段へ戻る・半角にそろえました・保存しています・保存の失敗 → terms。⑤`save_failed` を `saving` の次に足し、テスト 2 件。
- 消したファイル 2（49 行）。画面の非テスト行 557 → 539（−18。`StepField` 23 行を足したぶん）。テストは 1 件も消さず 27 件
- 挙動の変更：全角を直した知らせの出し方は「補足の末尾に空白で続ける」になり、読み上げの説明は「例：060-0042 半角にそろえました」の順（旧：先頭）。前後の空白を除いただけでは言わない。郵便番号・電話・登録番号は空白をすべて除いて読む。欄の外側の幅の上限は `Field` に付く
- `?state=save_failed` は、3 段目の入力と失敗の知らせを最初から出す。押し直しても失敗する（状態名で結果が決まる）。保存の内容は取引先なしのとき取引先の 3 欄を空にして渡す
- 数えて出た穴：シナリオ 1〜3 のテストの直書き（必須数・電話・段の名前）。欄の表と `STEP_NAMES` から引く形に直した
- 下に固定した帯が最後の要素を隠す件は土台で直っていた（ui-audit `fixed-band-last-item` 合格）。離れる窓は持たない（F-09 の対象外）ので `dirty` は渡していない
