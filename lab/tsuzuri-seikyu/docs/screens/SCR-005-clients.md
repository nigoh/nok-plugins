## 1. この画面で人がすること、最初の 1 画面

- 登録してある取引先を名前か読み仮名で探し、取引先ごとの未入金額と支払期限が近い（過ぎた）請求書の有無を確かめる
- 取引先名を押して編集へ移る。新しく加えるときは主ボタン「取引先を登録する」
- 最初の 1 画面（375×812）：見出し → 探す欄（補足つき）→ 並び順 → 条件と合計の 1 文 → 一覧の先頭 3〜4 行。主ボタンは下に固定。説明文は置かず、更新できなかったときの知らせだけ一覧より先に出す

## 3. 判断の記録

- D-01：並び順の選択肢 2 個・最長 8 字・同時に 1 つ・値を選ぶ意味（別の場所へ移らない）→ セグメント。タブにしない
- D-02：2 個が 375px の 1 行に収まる（8 字×14px＝112px＋32px、5 字で 102px、合計 ≈254px ＜ 343px）→ セグメント。スイッチにしない（オンオフの意味でない）
- D-04：主ボタン「取引先を登録する」1 つ。取引先名は別の場所へ行くだけ → リンク。探す欄の × は読み上げ名つきの絵のボタン 1 個。0 件（条件）の「探す語を消す」は主ボタンと別の操作 → `EmptyState` の `action` に置くふつうのボタン
- D-05：ボタンが並ぶ所は 0（見出しの右は主 1 つ）。「取引先を登録する」8 字＝112px＋32px＝144px ＜ 帯 343px → 横 1 個で収まる
- D-06：文字の段 3 つ＝22（見出し）／16（入力欄）／14（本文・表・補足）。ui-audit が測った段も [14, 16, 22]。「2件」「3日超過」は判断に使う値 → 12px にせず 14px の `muted`
- D-07：探す欄・並び順・1 文・表・ページ送りは 1 つのまとまりで、間はスマホ 16・768px 以上 24。1 文と表の間だけ 8（1 文が表の説明）。刻みに無い余白は 0/261 か所（ui-audit）→ 節の間 32／48 より小さく保つ
- D-08：取引先名・担当者・締め日と支払期限は左揃え、未入金額は見出しも数も右揃え・等幅。補足は金額の下で右揃え → 字下げは使わない
- D-09：取引先名は最長 60 字 → 折り返して全部見せる。数字と単位・日付と曜日は nowrap。締め日と支払期限は「月末締め・」「翌々月10日払い」の 2 塊、補足も「・」で区切った塊の間だけで折り返す
- D-10：1 文（条件・並び・合計）は表の直上。税込は列見出しと 1 文の両方 → 離れた注記にしない
- D-11：担当者・条件・金額を同じ軸で見比べる、14〜200 件 → 表（`DataTable`）。面にしない
- D-13：境目は `DataTable` の枠 672px。取引先名の列は枠 672px で 176px（≈12 字/行）、704px で 208px、992px で 496px。60 字は 672px で 5 行、992px で 2 行 → 折り返して項目を落とさない。375px は行の形（取引先名が頭）。列の優先順は 取引先名 → 担当者 → 締め日と支払期限 → 未入金額
- D-14：主役＝取引先を探して未入金額を確かめる → 探す欄と並び順を見出しの次に、一覧の頭を 1 画面目に入れる。知らせは stale のときだけ先頭
- E-02：状態名は screens.yaml の 8 つのまま → 足さない
- E-03：保存・窓・競合が無い → `save_failed`・`conflict`・`done` は none（理由は 2 の表）
- E-04：refreshing は前の表を残し、止めるのは並び順とページ送りだけ。探す欄は止めない（手元の絞り込み）。stale の確定する操作は 0 → 押せなくする物は無い。ただし未入金額は古い → 知らせに「未入金額は更新前の金額です」と書く
- E-05：0 件は 2 種類。初回は説明＋文中リンク、見出し右に主ボタンがあるので同名のボタンを重ねない（決定 9）。探す語に合わない 0 件は適用中の語を見せ「探す語を消す」→ 作る導線は主にしない
- E-06：初回の失敗は ErrorState を本体の位置に（role=alert）。更新の失敗は先頭の StaleNotice。押した所に処理中が出る
- E-07：読むだけの初回失敗。`autoRetry`（自動 2 回）は使える → 挙動が変わるので入れず、手動のまま（決める人に報告）。stale の自動は 0 回
- C-03：期限は絶対の日付が主、相対（あと12日・3日超過・今日まで）は 14px の `muted`。超過の日数が増えても調子を上げない → 色で塗らない。状況の札は出さない（請求書の状況の列が無い）
- C-05：藍は主ボタンの塗り 1 個、取引先名のリンクの文字、選んでいる並び順の地と 1px の線 → 塗りは 1 か所
- C-06：金額・件数・日数は `fg`、補足は `muted`。未入金額は増えると悪い → 色を付けず、件数と最も早い期限を隣に書く
- C-07：画面全体の知らせは stale の 1 つだけ（2 つまで）。行の地・左端の太線で強調しない（選択中と衝突）
- C-09：押せない（refreshing の並び順・ページ送り）は部品の `disabled` が薄くする。薄くしない理由の文「更新しています。並び順とページは変えられません」を近くに置く
- G-01：項目ごとの正確な値（1 円まで）を見比べる、主張が無い → 図にせず表
- G-04：列の順 探すもの → 担当者 → 条件 → 金額（右端）。既定は読み仮名順。いまの並びは 1 文でも言う。並べ替えは表の外の選択で行う → 見出しに `aria-sort` は付けない
- G-05：金額は桁区切り・1 円まで・単位は見出し「未入金額（税込・円）」、1 文では数字の直後に「円」 → 整形は `lib/format` から引く
- G-06：未入金が計算して 0 → 「0」（欠けでない）。請求書が取れなければ `error`・`stale` で、欠けを 0 にしない
- G-07：期限は一覧の短い形（10/31(土)）。同じ列に今年以外が 1 件でもあれば全行を長い形 → `formatDateColumn` に列ごと渡す
- F-03：探す欄が 1 つ・必須 0 → 印なし。ラベル「取引先を探す」6 字を欄の上に、補足「取引先名か読み仮名で探せます。例：ほくと」を常時 14px 以上で。プレースホルダー 0
- F-05：他人（取引先）の情報を探す欄 → `type=text`・`inputMode=search`・`autocomplete` なし・最大 60 字（名前の最長）。文字 16px・高さ 44px
- F-06：全角・半角・ひらがな・カタカナ・半角カナ・空白・英字の大小・中点を同じ語として受ける → `foldForSearch` を探す語と名前の両方にかけて比べる。欄の文字は書き換えず、「半角にそろえました」も出さない（保存する値でない）。探す対象は名前と読み仮名だけ。担当者名は探さず URL にも入れない（REQ-027）
- L-07：初回は題＋文中リンク入りの 1 文、条件の 0 件は題＋適用中の語＋消す手段 → 「まだ」は初回だけ
- L-08：待ちは「取引先の一覧を読み込んでいます」、更新中は「更新しています」、再読み込みの処理中は「読み込んでいます」 → 後の 2 つは terms から引く
- L-12：取引先名のリンクの読み上げ名は「株式会社北斗印刷を編集する」。見える名前を含め、足す「を編集する」だけ見えない文字 → 同じ行き先は同じ文言
- L-13：この画面にしか出ない文は `copy.ts` 1 か所。更新中・更新できなかった・処理中は `StaleNotice`・`RefreshingNote` が terms から引く → 画面に同じ文を持たない
- S-02：表・探す欄は 1 画面だけで使う → 画面のフォルダに置き、CMP-ID は付けない
- S-07：探す語・並び順・ページは人が戻って来たい状態 → URL（`q`・`sort`・`page`）に持ち、既定の値は書かない。条件を変えたらページを外す（1 度の `replaceParams`）。行・件数・合計は計算できる → 持たない。画面の状態は `?state=` の列挙 1 つ
- A-05：探す・並べる・ページ送りは 1 日に何度も行う → 結果の入れ替えは動かさない。ページを送った所だけ、新しいページの 1 文へフォーカスを移す（次へを押した位置のままだと新しいページの終わりを見るため）

## 7. 構造の設計図

- 部品の木：
  `取引先（画面）　取るデータ：useFake → 行（取引先＋未入金額）。URL：q・sort・page（useUrlParam）`
  `├ StaleNotice・RefreshingNote（土台 CMP-040）`
  `├ ListControls（画面内）　探す欄（Field＋TextInput＋IconButton）・並び順（Segmented の disabled）`
  `├ ClientsTable（画面内）→ DataTable（parts）→ Link・Money`
  `├ Pagination（ui。pageSize を渡さない）`
  `└ model.ts（行を作る・探す・並べる）／fixtures.ts（200 件の見本）／copy.ts（文言）`
- S-01：取引先名のリンクは文字だけ。× ボタンは `input` の兄弟。表のセルの中の `div` は `DataTable` が許す形。見出しは h1 だけ、`role=search` に名前、`nav` は「主なメニュー」「ページ送り」を区別
- S-10：見た目の順＝DOM の順（知らせ → 探す・並べる → 1 文 → 表 → ページ送り）。`order` を使わない

## 8. 動きの仕様

新しい動き 0。基本の部品が持つ応答（ボタンの押した縮み・色）だけ。

動かさない物（A-05）：探す・並べ替え・ページ送りの結果の入れ替え（1 日に何度も行う）、更新中の文（回る印も出さない）、stale の知らせ、0 件・失敗の表示。印になる動き（A-06）は頻繁に通る一覧に置かない。

## 9. 実装で変えたこと

- 置き換え 6 件：URL の値（`useListQuery` → `useUrlParam`＋`replaceParams`）、ページ（`pageOf`・`PAGE_SIZE` → `paginate`＋`Pagination`）、古い内容・更新中（自作の Notice と文 → `StaleNotice`・`RefreshingNote`）、押せない（`fieldset disabled` → `Segmented`・`Pagination` の `disabled`）、探す語（NFKC の自作 → `foldForSearch`）、初回の 0 件（主と同名のボタン → 文中リンク）
- 挙動が変わった所：初回の 0 件の次の一手がボタンから文中リンクになった（決定 9）。更新中の文が「更新しています。更新が終わるまで、並び順とページは変えられません。」から「更新しています。並び順とページは変えられません」になった（土台の文型）。探す語は中点「・」も除いて比べる
- テスト：置き換えで意味が無くなった `searchKey`・`pageOf` の確かめは `foldForSearch`・`paginate` に直した。0 件の確かめに「ボタンを重ねない」を足した
- 変更シナリオ 3 で出た穴を直した：ページの件数をテストが直書きしていた
- filtered_empty の最初の語：土台に決まりが無いので画面の state で持つ（URL の値は `useUrlParam` の既定の値にすると、消しても戻ってしまうため使えない）
- 下に固定した帯が最後の要素を隠す件は土台で直った。ui-audit の `fixed-band-last-item` は 8 状態で合格
- 足りなかった物（土台）：画面固有の「見本の語を最初に入れて開く」を `useUrlParam` が持てない（既定の値にすると、消しても見本の語へ戻る）
