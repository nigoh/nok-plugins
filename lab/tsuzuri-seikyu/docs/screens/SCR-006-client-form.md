## 1. この画面で人がすること、最初の 1 画面
- 取引先を新しく登録する（`?screen=client-form`）か、登録済みの取引先を直す（`&id=c03`）。取引先名と宛先のメールがあれば保存できる。住所・支払いの条件・担当者は分かる分だけ入れる。
- 最初の 1 画面（375×812）：戻り → 見出し → 説明 1 文（新規だけ）→ 取引先名 → ふりがなの頭。下に固定の「やめる」と主ボタン。

## 3. 判断の記録
- D-01：支払期限の「月」3 個・最長 3 字・保存で確定 → セグメント。節 3 つは全部を読む → 縦に並べ、畳まない
- D-02：締め日・支払日の「日」6 個（月末・5・10・15・20・25）→ セレクト。住所の候補 2〜5 個 → ラジオ（`Radio` plain。当たり 44px 四方は部品が持つ）
- D-04：押せる操作 4 種（登録・足す・消す・やめる）→ 主は 1 つ（新規「取引先を登録する」・編集「保存する」）。「担当者を足す」は副、「消す」は quiet、「やめる」は移動なのでリンクの形（`LinkButton`）
- D-04：取り返しのつかない操作は窓の「保存せず離れる」だけ → danger。並びの左端（主から離す）
- D-05：下に固定の帯・2 個・最長 8 字・8 字×14px＝112px＋余白 32px＝144px ＜ 1 個 167px（375px） → 横 2 つ
- D-05：離れる窓・3 個・19 字×14px＋余白 96px＋間 16px＝378px。内側 464px（md 以上）は収まる → 横、375px は 343px で収まらない → 縦で主が下（骨格の窓の既定）
- D-13：支払期限の月 230px＋日 112px＋間 12px＝354px ＞ 343px（375px 幅）→ 768px 未満は縦、以上は横
- D-10：「送った請求書は変わらない」は編集でだけ当てはまる → 編集のときだけ欄の補足に置く。離れる前の注意 → 窓の本文
- D-14：最初の 1 画面（375×812）に入る主役 = 取引先名の欄 → 見出しの次に置く。説明は新規だけ 1 文。出す知らせの事実が無い → 先頭に知らせは置かない
- C-05：藍の塗りは主ボタン 1 つ → ラジオの選択は線と太い縁まで、他は文字・線
- C-10：誤りの文字 = `bad-text`＋絵＋文＋枠 → 色だけにせず、4.5:1 は土台の色の対（ui-audit axe-serious 0 件）
- E-02：通信で失敗する操作が 2 つ（登録・保存）→ どちらも `save_failed`。補完の失敗 `zip_error`（相手側の障害でほかを止めない）とは別
- E-06：保存の失敗 → 末尾の操作の直上に Notice（role=alert）、入力は残す。補完の失敗 → 郵便番号の隣
- E-07：書き込み（保存）→ 自動で繰り返さず、押し直しだけ。補完は表示中の更新 → 自動 0 回で「住所をもう一度探す」
- E-08：保存＝戻せる・届かない・期限に関わる → 窓なしで確定後に知らせる。編集だけ「元に戻す」。担当者の削除 → 窓なしで「元に戻す」。離れる（入力が消える）→ 窓
- E-09：連打・変換中でない Enter の再押下 → 押した瞬間から押したボタンだけ処理中、1 回だけ効く（`busy` の ref）。保存中は `dirty` を false にして離れるガードを外し、やめるを押せなくする
- F-01：項目 11（担当者は 1 行 4 欄で 5 行まで）・塊 3（9〜20 個）→ 1 画面に節 3 つ
- F-03：欄 11（担当者 1 行のとき）・必須 2（取引先名・1 人目のメール）＝半分より少ない → 必須の 2 欄に「必須」。担当者を足すと欄の数だけ増える（`fieldCount`）。プレースホルダー無し、例は補足に 1 つ
- F-04：形式の誤りが出る欄 4（ふりがな・郵便番号・メール・電話）→ 離れた時に欄の直下へ。空の必須は送る時だけ。2 件以上で先頭に一覧（role=alert・フォーカスは移さない）、フォーカスは最初の誤り欄
- F-05：値の種類 4 → 郵便番号 text＋numeric、電話 tel、メール email。他人の情報（取引先名・住所・担当者）には autocomplete を付けない
- F-06：全角・ハイフンの種類・半角カナ → 離れた時に `toHalf`・`toHalfDigits`・`toKatakana` で直す。前後の空白を除いただけ → 「半角にそろえました」を言わない（`wasWidened`）。郵便番号 7 桁 → 住所を探し、空の欄にだけ入れる
- F-07：初期値の出どころ = 設定の標準の条件（新規）→ 出どころを書き、直したら消す。編集で開いたときの保存値 → 標準で書き換えない
- F-08：担当者 4 欄・最大 5 行 → 縦に積み、行ごとに見出しと区切り線。最後の 1 行に「消す」を出さない。並びに意味が無い → 並べ替えは作らない
- F-09：下書きの状態が無い・3 分以内 → 自動保存しない。変更があるときだけ骨格の窓（保存して離れる＝主・入力に戻る・保存せず離れる）
- F-10：主は入力の末尾の右（768px 以上）、未満は下に固定。順はやめる→主、DOM も同じ。必須が空でも押せる。成功は一覧へ移り知らせる
- F-11：新規と編集 → 同じ欄・順・誤りの文。変えるのは見出し・主ボタン・補足の 1 文・初期値だけ
- L-03：窓の副「入力に戻る」5 字（決定 9）→ 骨格の語を引く。処理中の主は 7 字以内
- L-06：失敗の文 = 何ができなかったか＋入力は残る＋次の一手 → 登録は主の動詞に合わせ「登録できませんでした」、編集は標準の「保存できませんでした」
- L-13：画面にしか出ない文 → `copy.ts`。保存しています・半角にそろえました・離れる窓・保存の失敗（編集）は `app/terms` から引く

## 9. 実装で変えたこと
- 今回の置き換え 6 件：①離れる窓（`useLeaveGuard.ts` 38 行・`LeaveDialog.tsx` 28 行・`leaving` の state）→ 骨格の `dirty`・`onSaveBeforeLeave`。②`validate.ts` の NFKC・全角判定・かな直し → `lib` の `toHalf`・`toHalfDigits`・`wasWidened`・`toKatakana`。③`save.ts` 10 行 → `fakeSave`＋`outcomeOf(state)`（失敗は値で受ける）。④`AddressChoice.tsx` 31 行 → `RadioGroup`＋`Radio`。⑤`texts.ts` → `copy.ts`（保存しています・半角にそろえました・離れる窓は terms へ）。⑥`save_failed` を `saving` の次に足し、テスト 2 件
- 消したファイル 4（107 行）。画面の非テスト行 1014 → 896（−118）。テストは 1 件も消さず 65 件
- 挙動の変更：離れる窓の並びと文言は同じで、骨格の窓になった。「やめる」はリンクの形（`LinkButton`）で、保存中は押せない。郵便番号・電話は空白をすべて除いて読む（「060 0042」を受ける）。
