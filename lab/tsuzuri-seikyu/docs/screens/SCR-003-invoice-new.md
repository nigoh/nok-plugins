## 1. この画面で人がすること、最初の 1 画面

- 取引先を選び、明細（品名・数量・単価・税率）を足す。合計は入れるたびに出る。途中なら「下書きを保存する」、揃ったら「内容を確かめる」で窓を開き、宛先・合計・期限を見て「請求書を送る」。
- 最初の 1 画面（375×812）：戻り（← 請求書）→見出し→節「宛先と期限」の取引先・請求日→下に固定の「下書きを保存する」「内容を確かめる」。主役は取引先と明細。説明や知らせを前に置かない。

## 3. 判断の記録

- D-01：節 3 つ（宛先と期限・明細・備考）を順に読み、合計は明細と見比べる → 縦に並べる。タブにしない
- D-02：取引先 14 件（最大 200 社）→ 15 件以下は Select、16 件以上は絞る欄＋Select。税率は 2 択・ラベル 3 字 → Segmented
- D-03：金額・数量は正確な値が要る → type=text の入力欄。スライダー・type=number にしない
- D-04：主は「内容を確かめる」1 つで藍の塗り 1 → 「下書きを保存する」「明細を足す」は枠、「明細Nを消す」は quiet（戻せる）、取引先の登録は文中リンク
- D-05：下の帯・ボタン 2 個・最長 8 字・375px で 1 個 167px（内側を引いて 139px は 14px で 9.9 字）→ 横 2 つ。送る窓（2 個）は 375px で縦、主が下。処理中の文言は 7 字「保存しています」で幅を保つ
- D-06：文字の段は 22・16・14px の 3 つ、余白は gap-6（24px）と gap-2（8px）→ 12px は使わず、明細は面にせず border-t＋pt-6 で分ける。数量・単価・金額は右揃え（Money）
- D-09：取引先名 最長 33 字（上限 60）→ Select で切れるので、選んだ取引先の全文を欄の下に折り返して出す。取り消せない注意は窓の中・ボタンの直前（D-10）
- D-11：明細は 1 行 5 欄（品名・数量・単位・単価・税率）→ 表にせず行ごとに縦に積む（`ol > li`、名前は「明細N」）
- D-13：明細 1 行は枠幅 576px（`@xl`）で組み替え。576px の 3 列は (576−2×16)÷3＝181px ≥ 176px → 未満は縦 1 列、以上は品名全幅＋［数量・単位・単価］3 列＋［税率・金額］
- D-14：主役は取引先と明細 → 説明・知らせは先頭に置かず、利用者が選ぶ必要のある知らせ（競合・失敗）だけ先頭
- C-05：藍は主ボタンの塗り 1 つ、窓の主は窓が開く間だけ（背面は inert）→ ほかは文字・線まで
- C-06：金額・件数に色を付けない → fg と muted だけ
- C-07：状況の札は 0 枚（番号が付く前は状況を持たない）。知らせは同時に最大 1（invalid＝一覧、conflict＝warn、失敗＝fail）→ 札は使わず知らせだけ
- E-01：5 軸を見直した結果、足りなかった状態は 1 つ（保存・送るの失敗）→ `save_failed` を足し、`saving` の次に置く
- E-02：下書きの保存と送るの失敗の 2 つ、見え方が別 → どちらも `save_failed` 1 つで受ける。何の操作かは文言（下書き＝先頭、送る＝窓）
- E-06：通信の失敗は押した所の近く。下書き＝先頭の知らせ（欄が分からない）、送る＝窓の中、入力の誤り＝欄の直下、競合＝先頭 → どれも role=alert か status、入力は残す
- E-07：読み込みの失敗は手動の「もう一度読み込む」、書き込み（下書き・送る）の自動再試行は 0 回（二重に起きない）→ 手動のみ
- E-08：送る・戻せない・メールが届く・番号が付く → 窓。明細を消す・戻せる・届かない・お金が未確定 → 窓なしの「元に戻す」（10 秒）
- E-09：選んだ取引先の支払条件を別の人が先に変え、支払期限が食い違う（新規作成で上書き先が無い）→ 違う項目だけ並べ「この内容で保存する」「新しい期限を使う」。選ぶまで保存・確かめるを止める
- F-04：形式の誤り（日付・数・期限の前後・合計の上限）は離れた時に欄の直下、空欄の必須は送る時。送った時に 2 件以上なら先頭に一覧（role=alert・フォーカスは移さない）、最初の誤り欄へ → 明細の文は「明細2の」と行を入れる
- F-05：数量は小数がある（0.5 日）→ inputmode=decimal、単価は numeric＋後ろに「円」。取引先は他人の情報 → autocomplete なし
- F-06：全角の数字・ハイフンの種類・桁区切り・「円」・和暦・「11月13日」を受ける → 離れた時に半角（単価は桁区切り、日付は「2026年11月13日」）へ直し、直したときだけ「半角にそろえました」。前後の空白だけでは言わない
- F-07：支払期限は取引先の支払条件と請求日から入れる（締め日を過ぎた請求日は翌月分）→ 人が直したら手を引き、欄の近くに「自動に戻す」。自動で変えたときは role=status で知らせる
- F-08：明細は 4 欄以上 → 行ごとに積み、追加は「明細を足す」で品名へフォーカス、削除は「明細Nを消す」（最後の 1 行は出さない）。並びに意味が無いので並べ替えは作らない
- F-09：下書きの状態がある（請求書）→ サーバーの下書きは「下書きを保存する」でだけ作る。未保存で離れるときは骨格の窓（保存せず離れる→入力に戻る→保存して離れる）。必須が欠けていたら移らず窓を閉じ、欄の直下に誤りを出す
- F-10：「内容を確かめる」は 768px 以上は入力の末尾の右、未満は下に固定。必須が空でも押せる（誤りを出す）。成功は詳細へ移り知らせる（戻っても再送しない）
- F-11：請求書の番号は送るときに付く → 入力欄にせず、合計の下の 1 文で言う
- G-05：金額は半角・桁区切り・1 円まで、表の列は見出しで円（ここは Money）。税は税率ごとの小計に 1 回だけ、設定の端数処理（切り捨て・四捨五入・切り上げ）を文で言う
- G-06：数量か単価が揃わない行（金額なし）、計算できる明細 0 行の合計 → 「—」（0 にしない）。揃わない行は合計に入れず、その数を知らせる
- L-03：同じ操作は全画面で同じ名前、最長 9 字、窓の題と主は同じ動詞 → ボタンは terms の `actions` から引く
- L-13：画面にしか出ない文 → `copy.ts` に集め、数と名前は差し込む。全画面で同じ文（保存しています・保存できませんでした…・半角にそろえました）は terms の `messages`
- A-05：合計と各行の金額は入れるたびに変わる → 数え上げの動きは付けない。誤りは揺らさない

## 9. 実装で変えたこと

置き換え 7 件（plan の 7 件すべて）：
- 離れる確かめ：自作の見張り・窓・流れの `leave` の種類を、AppShell の `dirty` と `onSaveBeforeLeave` に替えた（`useLeaveGuard.ts`・`LeaveDialog.tsx` を削除）。窓は 保存せず離れる→入力に戻る→保存して離れる（「編集に戻る」をやめた）。ブラウザの戻るでも窓が出る
- 日付・金額の読み：`dateInput.ts`・`numberInput.ts` を削除し lib の `readDate`・`readYen(text, MAX_AMOUNT)`・`readQuantity(text, MAX_QUANTITY)` へ。挙動の違い：日付の年は 1900〜2100（0001 年などは誤り）
- 離れた時にそろえる形・探す語：`settleDate`・`settleYen`・`wasWidened`・`foldForSearch`。数量だけ土台に settle が無く、`formLogic.ts` の `tidyQuantity` に残した。全角空白だけ・前後の空白だけでは「半角にそろえました」を言わない（テスト 1 つ追加）。探す語は中点・全角空白も除くようになった
- 保存：`save.ts` を削除し、既定を data の `fakeSave` を包む `fakeSaveFn` に。`save` を注入する形（テスト）は引数のまま。待ちは 600ms の 1 つ（テストは fake timers で `SAVE_WAIT_MS` 進める）
- 文言：保存しています・保存できませんでした…・半角にそろえました は terms の `messages`。tsx に直書きしていた文は `copy.ts` に集めた（誤りの文を含む）
- `save_failed` を states に足した（`saving` の次）。テストを 3 つ足した（下書き・送る・競合では失敗にならない）
