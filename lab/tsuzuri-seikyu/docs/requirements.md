# つづり請求 要件（試作 第3回）

小さな事業者（1〜10 人）が、請求書を作り、送り、入金を確かめる業務ツール。性格は「静か・数字が主役・急かさない」。
形式：REQ-ID／題／受け入れ条件（前提・操作・期待結果）。範囲外は末尾に書く。画面との対応は `.konomi/screens.yaml` の covers。

## 目標と前提（R-02・R-15・R-10）
- 対象：iOS Safari 最新 2 世代、Android Chrome 最新、Chrome、Edge、Safari。幅は 375・768・1280 の 3 段で確かめる。最小幅 360。
- 準拠：JIS X 8341-3:2016 / WCAG 2.2 レベル AA。性能：1 枚 HTML 300KB 以内（gzip 100KB）、LCP 2.5 秒以内（見本データ、CPU 4 倍減速）。
- 言語は日本語のみ。日時は保存を UTC、表示を日本時間（Asia/Tokyo）。金額は円の整数。通信はしない（見本データと偽の取得）。
- 件数の想定（R-03）：請求書 平均 40 件／月・最大 1,000 件、取引先 最大 200 件、明細 1 通あたり 平均 3 行・最大 50 行、取引先名 最長 60 字、金額 最大 99,999,999 円。

## 共通

**REQ-001 共通の骨格**
- 前提：どの画面でも。操作：開く。期待：メニュー（ホーム・請求書・取引先・入金の確認・売上レポート・設定）が同じ並びで、現在地が示される。`main` は 1 つ、`h1` は画面の呼び名、主ボタンは 1 つで同じ位置（見出しの右／スマホは下に固定）。詳細・入力画面には左上に行き先の名前つきの戻りがある。

**REQ-002 状況の呼び名と札**
- 前提：請求書と入金に状況がある。操作：一覧・詳細・ホームで見る。期待：請求書は 下書き／送付済み／入金済み／期限超過／取り消し済み、入金は 未確認／確認済み／差額あり。札は絵と言葉を持ち、色だけで伝えない。呼び名は terms のとおり全画面で同じ。期限超過は、送付済みで支払期限が今日より前のものから計算する（保存しない）。

**REQ-003 金額と日付の表示**
- 期待：金額は桁区切り・等幅の数字・右寄せ・単位「円」（表の列は見出しに単位）。日付は「2026年11月13日」形式、一覧では「11/13(金)」。整形は Intl で 1 か所。数値の欠損は 0 と別の表記（「—」）。

**REQ-004 合計の自動計算**
- 前提：明細は税抜単価×数量、税率は 10% と 8%。操作：明細を足す・直す・消す。期待：小計・税率ごとの消費税・合計が即座に更新される。税は税率ごとの小計に 1 回だけ、設定の端数処理（切り捨て・四捨五入・切り上げ）で計算する。

**REQ-005 用語の統一**
- 期待：画面の文言に terms の避ける言い方（ステータス・顧客・送信・発行・キャンセル など）と設計の言葉（状態名・ID・「空状態」）が出ない。「請求書を送る」は、番号を付けて相手に送る 1 つの操作で、発行と送信を別の語にしない。

**REQ-006 幅 3 段階の見え方**
- 操作：375・768・1280 で開く。期待：横スクロールが出ない。表は枠の幅で行の形に組み替わり、項目を落とさない。スマホはメニューが「メニュー」ボタンから出る。

**REQ-007 アクセシビリティ**
- 期待：キーボードだけで全操作ができ、focus-visible の輪が出る。押す範囲は 44px 以上。コントラスト 4.5:1（枠 3:1）。axe の違反ゼロ。動きを減らす設定で移動・回転が止まる。入力欄の文字は 16px 以上。

**REQ-008 待ち・空・失敗の見せ方**
- 期待：読み込みは実際の配置と同じ形の骨組み（0.3 秒たってから）。0 件は理由と次の一手。失敗は何が起きたかと直し方、再試行の手段（押すと処理中になり、成功で立ち直る）。通信が無いときも失敗と同じ扱い。

**REQ-009 入力の誤りと入力の保持**
- 操作：必須の欄が空、形式が違う、で送ろうとする。期待：誤りは欄の近くに言葉で、最初の誤り欄へ移る。揺らさない。送る・保存の最中は押したボタンだけ処理中になり、二重に送られない。失敗しても入力は消えず、元の画面で再送できる。

**REQ-010 配信と性能**
- 期待：1 枚の HTML に固まり、外部の読み込みと外部フォントが無い。`lang="ja"`。上の性能の目標を満たす。

**REQ-011 権限・同時操作・通信断**
- 期待：権限の区別は無い（1〜10 人の事業所のため、全員が全部できる）。同じ内容を 2 人が開いてあとから保存したとき、「別の人が先に更新しました」と知らせ、上書きするか確かめる（設定と請求書の作成で表示する）。通信断は REQ-008 の失敗と同じ扱いで、入力を残す。

## 画面ごと

**REQ-012 ホーム**
- 期待：今月の請求額・未入金の額・期限超過の件数が、比較対象（先月）と時点つきで並ぶ。今日やること（期限超過の確認、未確認の入金、下書き）が件数つきで先頭にあり、押すと該当の画面へ。最近の動きは起きたことを「N分前」で言う。請求書が 1 件も無いときは、最初の請求書を作る導線を出す。

**REQ-013 請求書の一覧**
- 操作：状況で絞る、取引先名・番号で探す、支払期限・金額・日付で並べ替える。期待：適用中の条件が見え、個別に外せる。0 件になる条件でも外せる。20 件ごとのページ送り（件数つき）。条件・並び順・ページは URL に残り、戻る・再読み込みで同じ。PC は表、スマホは行の形。

**REQ-014 請求書の作成**
- 操作：取引先を選び、明細を足す・消す。支払期限は取引先の締め日から自動で入る。期待：合計が自動計算される（REQ-004）。「下書きを保存」で下書きになり、保存した旨を知らせて詳細へ移る。離れる前に未保存の入力があれば確かめる。

**REQ-015 送る前の確認**
- 操作：「内容を確かめる」を押す。期待：窓に、宛先・合計・支払期限・「送ると番号が付き、相手にメールが届きます」を出す。窓の「請求書を送る」で送り、成功で詳細へ移って知らせる。やめるで入力はそのまま。送る処理中は押したボタンだけ処理中。

**REQ-016 請求書の詳細**
- 期待：状況の流れ（下書き→送付済み→入金済み）で現在地が分かる。明細・合計・取引先・支払期限・履歴（起きたことと時刻）が見える。状況に応じた操作（下書き：送る・削除／送付済み：入金を記録・取り消す）。存在しない・削除済みは「見つかりません」と一覧への導線。

**REQ-017 入金の記録と取り消し**
- 操作：「入金を記録する」で日付と金額を確かめて記録。「請求書を取り消す」は確認の窓を経る。期待：記録で入金済みになり履歴に残る。取り消しは元に戻せないことを操作の直前に書く。

**REQ-018 取引先の一覧**
- 期待：取引先名・担当者・締め日と支払期限・未入金額を並べる。取引先名・かなで探せる。未入金額の多い順に並べ替えられる。20 件ごとのページ送り。0 件は登録の導線。

**REQ-019 取引先の登録・編集**
- 操作：名前・住所・締め日・支払期限・担当者を入れて保存。期待：必須は名前と宛先メール。締め日・支払期限は選択肢で入れる（月末／日付、当月・翌月・翌々月）。保存で一覧へ戻り知らせる。編集は同じ画面で既存の値が入る。保存せずに離れるときは確かめる。

**REQ-020 郵便番号の補完**
- 操作：郵便番号を入れる（全角・ハイフン無しも受ける）。期待：住所が補完される。複数に当たれば選ぶ。当たらない・時間切れのときは、手で入れられると知らせ、入力を消さない。

**REQ-021 入金の突き合わせ**
- 操作：未確認の入金ごとに候補の請求書（名義と金額から）を見て選び、確認する。候補が無ければ請求書を手で探して選ぶ。期待：選ぶと確認済みになり、請求書は入金済みになる。まとめて確認した結果が一部失敗したら、成功と失敗を分けて知らせる。

**REQ-022 差額のある入金**
- 期待：入金額と請求額が違うとき、差額（符号つき）と考えられる理由（振込手数料）を出し、「差額を手数料として確認する」か「確認せず戻る」を選べる。黙って確定しない。

**REQ-023 売上レポート**
- 期待：月ごとの請求額と入金額の図（棒は 0 始まり）、取引先別の内訳の表、期間（半年・1 年・今年度）の切り替え。図の文字は 14px 以上。集計の範囲と、確定していない月があることを書く。0 件の期間は理由を出す。

**REQ-024 書き出し**
- 操作：「書き出す」を押す。期待：表の内容を CSV で書き出す。最中は押したボタンだけ処理中で、終わったら知らせる。失敗は理由と再試行。

**REQ-025 設定**
- 期待：自社の情報（名前・住所・登録番号）、請求書の番号の付け方、税の端数処理、通知（スイッチ）を区分で切り替えて直せる。保存で知らせる。番号の付け方を変えても、既に送った請求書は変わらないことを保存前に書く。

**REQ-026 はじめての設定**
- 操作：自社の情報→請求の決まり→最初の取引先の 3 段階。期待：現在地と全体数が出る。途中でやめても、次に開いたとき続きから（入力が残る）。戻るで 1 つ前の段階へ。最後の段階の後はホームへ移る。

**REQ-027 URL と戻る**
- 期待：画面は `?screen=`、状態は `?state=`（見本用）、絞り込み・並べ替え・ページ・タブ・対象の id は URL に持つ。画面を移るときは履歴に積み、画面内の切り替えは積まない。個人情報は URL に入れない。

**REQ-028 構造の守り**
- 期待：層の向き（トークン←基本←組み合わせ←画面）を逆に取り込まない。色・余白・角丸・文字の大きさ・時間を直書きしない。違反はテストで失敗する。

本物の通信、PDF の作成、メール送信、複数事業所、権限の区別、多言語、印刷の体裁（別途設計）。
