# SCR-008 売上レポート（slug `report`、種類：数字と図）
covers：REQ-001・003・006・007・008・023・024・027　states：default・loading・error・empty・filtered_empty・many・partial・saving・refreshing・stale

## 1. この画面で人がすること、最初の 1 画面
- 期間（半年・1年・今年度）を選び、月ごとの請求額と入金額の増減を見る。取引先別の内訳で、どこからの請求が多いかを見る。必要なら表を CSV に書き出す。
- 最初の 1 画面（375×812）：見出し → 期間の選択 → 図の題・期間・要約 1 文・凡例 1 行 → 月ごとの図。主ボタン「表を書き出す」は下に固定（768px 以上は見出しの右）。注記・月ごとの表・取引先別は図の下。

## 3. 判断の記録
- D-02：期間 3 個・最長 3 字（14px で 42px＋左右 32px＝74px）×3＋8＝230px ＜ 343px・選んですぐ反映 → セグメント（Segmented）1 行。ラジオにしない
- D-04：この画面の主操作は「表を書き出す」の 1 つ、ほかは知らせの中の「もう一度読み込む」だけ → 主は骨格の口へ。移動は文中リンク
- D-06：使う大きさは 12（目盛り）・14（本文・図の文字）・16 太字（区画見出し）・22 太字（骨格の h1）の 4 段、大きな数字を作らない → 28 は使わない
- D-09：数値と単位・取引先名は最長 60 字・月の目盛りは 1 行 → 数値は折らず（Money は nowrap）、取引先名は折り返して全部見せる
- D-10：数字の範囲（請求日か入金日の月か・税込）と途中の月は判断に要る → 図のすぐ下に常に見せる。書き出しの説明も同じ場所
- D-11：取引先別は同じ軸（請求額・入金額）で見比べる 14 社（最大 200） → 表（DataTable）。672px 未満は行に組み替わる
- D-12：図が主役・2 系列で直接ラベルが収まらない（1 組 48px ＜ 「入金額」42px＋棒） → 見出しの次に図、凡例は図の直上 1 行。文字は 14px 以上・目盛り 12px。棒は押せない（操作は主ボタンと表）
- D-13：9 点以上（1 点 24px ＜ ラベル 30px）かつ枠 512px 未満 → 月の名前を 5 つに間引く。図の幅は枠いっぱいで、文字は縮めない（棒だけ伸びる）
- D-14：主役は月ごとの図、期間の選択は図を変える → 期間を図の前に 1 行。知らせは操作が要るときだけ図の上に置く
- C-05：藍の塗りは主ボタン 1 つと図の主系列（C-11 が許す）、選択中のセグメントは ai-soft＋線 → 図の藍は 375px・半年で 6 組×約 16px×平均 110px≒10,500px²、全長約 2,800px×375px の 1.0%（計算）
- C-06：金額・増減は色を付けない → Money は fg のまま、増減は言葉で言う。数字だけの画面なので状況の札は使わない
- C-07：同時に出る知らせは最大 2 つ（一部失敗＋書き出し失敗）→ 知らせ枠 2 つまで、札は使わない
- C-09：期間を押せない間は更新中・書き出し中の 2 通り → 期間は disabled にし、理由を「更新しています。表を書き出せません」（role=status、aria-describedby）で言う
- C-10：棒の藍と灰は地に 3:1 以上（line-strong は明 3.04・暗 4.31）・同じ数字が表にある → 図の線の 3:1 は免除。文字は fg・muted
- C-11：2 系列 → 請求額を藍、入金額を灰（line-strong）、途中の月は枠だけの棒。凡例の語で区別して色だけにしない
- E-03：期間の切り替えがある → refreshing・stale を none にしない。forbidden・expired・not_found・invalid は screens.yaml の none（REQ-011・027・023）
- E-04：期間の切り替えの待ち（前の図あり）・更新失敗 → refreshing は前の図を残し骨組みなし、stale は「09:30時点の内容です」。書き出しは表と同じ数字を出すためどちらも止め、図を見る・戻るは止めない
- E-05：初回 0 件・期間 0 件 → 初回は説明 1 文＋文中リンク（見出し右の主ボタンと同名のボタンは置かない）、期間 0 件は条件（期間）を見せ広げる手段を 1 つ
- E-06：失敗の置き場所 3 種 → 読み込み失敗は ErrorState を本体の位置に、一部の月の失敗は図の上の知らせ（取れた月は残す）、書き出し失敗は図の上に role=alert
- E-07：読むだけの失敗 → 土台の自動 2 回は付けない（ui-audit が自動のやり直し中の loading と error を同じ見た目で撮り、states-distinct が落ちたため。9 に報告）。手動の「もう一度読み込む」のみ。書き込み（書き出し）は自動で繰り返さない
- E-08：書き出しは画面の数字を変えず相手にも届かず、お金・番号・期限に関わらない → 窓も「元に戻す」も置かず、終わりに短い知らせ「表を書き出しました」
- E-09：書き出しの連打 → 押した瞬間から busy で 1 回だけ。書き込みが無いので同時編集（conflict）は none
- G-01：値は 2 つ（請求額・入金額）×月 6〜12 点・形が主役 → 図（G-02）＋要約＋表。期間の合計 2 つは要約の文と表の合計行に出し、大きな数字にしない
- G-02：月の合計・6〜12 点、取引先は 5 社以上で名前最長 32 字 → 月は縦棒（0 始まり・2 系列は並べる）、取引先は横棒。5 社未満は表だけ
- G-05：文は全桁・円、最大が 1,000,000 円以上か未満か → 表は見出し「請求額（円）」で数だけ、目盛りは 100 万円以上なら万円（題に 1 回）、未満は円
- G-06：取れていない月・計算して 0 の月・当月 → 取れない月は棒なしで軸と表に「—」（読み上げ「データなし」）、0 の月は軸に「0」、当月は枠だけの棒と「（途中）」。合計は「6か月中4か月ぶん」と言う
- G-07：期間は同じ年かまたぐか・今年度の始まり → 同じ年は「2026年6月〜11月」、またぐなら両方に年、今年度は 4 月始まり（2026年4月〜11月）。月は図で「6月」、表で「2026年11月」
- G-08：最大が 36,300〜1,234,567 円で動く・目盛りは 3〜6 本 → 1・2・5 の刻み、上端は最大の次の刻み、単位は題に 1 回。期間を替えるたびに計算し直す
- G-09：系列 2 つ、取引先 11 社以上 → 凡例 1 行（図に接する）、取引先は上位 10＋「その他（n社）」の灰。図は上位だけ・表は全件
- G-10：期間の選択肢 3 個・既定は半年 → セグメントで、URL（`?period=`）に持つ。図・表・要約・書き出しは同じ期間。待つ間は前の図を残す
- G-11：月ごとの表は最大 12 行、取引先別の表は REQ-023 が必ず見せると決めている → 12 行以下は常に見せ、取引先別は 13 行以上でも畳まない（21 行以上はページ送り）。図ごとに題＋数字入りの 1 文
- G-12：書き出しは画面と同じ数字 → 同じ集計関数（`buildReport`）から。数はカンマなし・欠損は空欄・途中は「確定」列に「途中」・UTF-8（BOM つき）・名前に期間
- L-03：主ボタンの文言 → `actions.exportTable`（6 字）。処理中は「書き出しています」（7 字）
- L-04：区画の見出し 3 つ → 名詞で句点なし（月ごとの請求額と入金額（円）、月ごとの金額、取引先別の内訳）
- L-06：書き出し失敗 → 「書き出せませんでした」＋表の数字は残っている＋もう一度頼む。責めない・謝らない
- L-07：初回は説明が要り、期間 0 件は条件が要る → 「売上レポートはまだありません」＋1 文、期間 0 件は条件を言い広げる手段 1 つ。「データがありません」は使わない
- L-08：待ちと済みの知らせ → 「書き出しています」「表を書き出しました」（9 字、ボタンと同じ動詞）
- L-11：金額・税が文に出る → 金額は文でも全桁、税込と書く。数を含む文は対象を先に
- A-01：主ボタンの処理中 → 幅を変えない（Button が持つ）
- A-03：初回の読み込みと期間の切り替え → 初回は骨組み（0.3 秒後）、期間の切り替えは骨組みにせず前の図を残す。回る印は主ボタンの 1 つだけ

## 7. 構造の設計図
部品の木（層）：
- `index.tsx`（画面。URL の期間と状態を受け、取得を呼び、部品を置く）
  - `ReportBody.tsx`（置き方だけ。数字の中身を知らない）
    - `MonthlyChart.tsx`（図。月の行を受けて棒と目盛りを描く。取得を知らない）
    - `MonthlyTable.tsx`・`ClientBars.tsx`・`ClientTable.tsx`（DataTable・Money に列の定義を渡す）
  - `aggregate.ts`（請求書から月・取引先の行を作る純粋な関数）、`scale.ts`（目盛りと間引き）、`exportCsv.ts`（CSV 文字列とファイル名）、`copy.ts`（文）、`fixtures.ts`（見本の状態ごとのデータ）、`useExport.ts`（書き出しの待ち・失敗）

| 持つ物 | 置き場所 | 理由 |

## 8. 動きの仕様
新しい動き 0。動かさないもの：期間の切り替え（1 日に何度もする。A-05）、棒の描き直し、誤りの知らせ。待ちの骨組みと主ボタンの処理中は土台の部品が持つ。

## 9. 実装で変えたこと
- 土台に足りない物：`save_failed` が report の states に無い。書き出しの失敗を `?state=` で出せない（REQ-024 が失敗の表示を求める）。仮に、画面は `outcomeOf(state)` を使い、失敗はテストで `state="save_failed"` を渡したときだけ出る。
- 設計の変更：E-07 の自動 2 回（useFake の autoRetry）は付けない。付けた最初の点検で ui-audit の states-distinct が loading = error で落ちた。手動の「もう一度読み込む」のみ。
- 設計の変更：`many` の見本を土台の `manyInvoices` から自作に替えた（土台の見本は取引先が 4 社しか出ず 11 社に届かない）。
- 設計の変更：変更シナリオ 3 の見込みを 1 から 2 に直した。
