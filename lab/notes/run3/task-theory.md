konomi は「好みに沿った良いフロントエンドを、要件→設計→実装→テストまで一貫して作る」ための知識型スキル。
あなたは、その references/ に足す**理論の文書 1 本**を下書きする。担当の領域・ファイル名・ID の頭文字は依頼文にある。

2. /home/claude/konomi/skills/konomi/references/decisions.md（**書式の手本**。これと同じ作りにする）
3. /home/claude/konomi/skills/konomi/references/taste.md, structure.md, motion.md（重なり・矛盾を避けるため）
4. /home/claude/konomi/skills/konomi/laws/ のうち自分の領域に近い物（flow.md, visual.md, interaction.md, implementation.md, test.md, requirements.md）。**法則にすでにある事は繰り返さず ID で指す**。
5. 試作第3回の土台で出た気づき：/home/claude/konomi-run3/docs/foundation-notes.md
6. 実物：/home/claude/konomi-run3/app の .konomi/screens.yaml、docs/requirements.md、docs/foundation-decisions.md、src/ui/、src/parts/、src/data/（理論が実物でどう使われるかを確かめる材料）

## 書く物の形（decisions.md と同じ）
- 冒頭：何のための表か（2〜3行）／読む工程／調査日 2026-11-14／印の意味（〔調査〕〔原理〕〔目安〕〔試作〕）
- 使い方（4〜5行）
- 原理：表で 5〜8 個（ID は `<頭文字>P-1` から。例 CP-1）。広く知られた法則・指針から。言い換えを添える。
- 判断：8〜14 個（ID は `<頭文字>-01` から）。1 つごとに「問い」「軸（いまの画面の事実として測れる物）」「決め方の表（条件｜選ぶもの｜根拠）」。必要なら「やらないこと」「例（判断の記録の 1 行）」。
  - **条件は数えられる・見て分かる事実で書く**（「多い」ではなく「6 個以上」、「重要なら」ではなく「お金・取り消し・期限に関わるなら」）。
  - 数値には必ず印を付ける。指針で確かめた物は〔調査〕、自分で置いた物は〔目安〕。
  - 日本語の画面・日本の業務（請求、住所、氏名、和暦、円、全角半角、敬語）で変わる所は必ず書く。
- **設計段階で示す物**：この領域について、設計書に何をどんな書式で書けば「理論どおり」と人が確かめられるか。書式の見本を 1 つ（つづり請求の画面を例に）。
- **機械で確かめられること**：ブラウザで開いて測れる物／ソースを読んで測れる物を箇条書き（検査 ID の案、測り方、合否の線）。確かめられない物は「人が見る」と書く。
- **既存の文書との関係**：taste.md・decisions.md・structure.md・motion.md・laws と重なる所はどちらが正か。**直すべき矛盾**があれば「〇〇.md のこの行をこう直す」と具体的に（foundation-notes.md の指摘に自分の領域の物があれば必ず答えを出す）。
- 出どころ：WebSearch / WebFetch で**実際に確かめた物だけ** URL つきで書く（3〜8 件。WCAG 2.2、デジタル庁デザインシステム、NN/g、Material、Apple HIG、GOV.UK Design System など一次に近い物）。確かめていない物は本文で〔原理〕か〔目安〕にし、〔調査〕を付けない。

## 決まり
- 分量は 12〜18KB。表を主にし、文章は短く。同じことを 2 度書かない。
- 言葉：やさしい日本語。カタカナ語・略語は初出で言い換える。「〜すべき」より「〜する」。
- konomi の好み（白地、藍、静か、余白、数字が主役）と食い違う一般論は、好みを優先して書く。
- UI の例文は実際に画面に出せる文言で。設計の言葉（状態名など）を例文に混ぜない。
- 書く先は依頼文のファイル 1 本だけ。他のファイルは書き換えない。

書いたファイル、判断の ID と題名の一覧、既存文書の「直すべき矛盾」、機械で確かめられることの一覧、確かめた出どころの数。
