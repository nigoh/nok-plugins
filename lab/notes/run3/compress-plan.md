## 8. 質を落とさないための歯止め

**機械の照合**（`compress-trial/check.py`）。

| 照合 | 通る線 |
| --- | --- |
| 判断の ID（D-05・REQ-001・DOC-SIZE など） | 前の ID が後か置き場にある |
| 表のデータ行 | 前 ≤ 後＋宣言した移動行（移し先の同じ行も別に照合） |
| 数値（px・ms・字・%・:1 など） | 欠けは理由つきの許可リスト（例・経緯だけ可） |
| 印の数（〔目安〕〔調査〕〔原理〕〔試作〕〔要確認〕） | 種類ごとに減らない |
| 消した先への参照（`_moved` など） | grep で 0 |
| 本の KB・SKILL の行数 | 上限内 |

**試作の結果**：1 回目は 14 組中 10 組が不合格。本物の欠けは 6 組（F-06 の ID 6 個、states・color・form の印 3 個、words の ID 2 個、SKILL の 150・44px・500ms、design-doc の検査表 5 行の移動）。残りは例や経緯を消した分で、許可リストに書いた。直して 14 組すべて通した。**道具を通さずに縮めると、道が切れる**。

## 9. KNOWLEDGE.md に足す決まり（案）

「## 圧縮の決まり」として足す。

1. **足すときは同じ量を降ろす。** 足した KB 以上を同じ変更で置き場へ降ろす。降ろす物を書けないなら足さない。
2. **上限を決める**：理論 1 本 16KB、SKILL 11KB、点検表 1 本 6KB、役割別の読む量は第 1・第 2 目標。`wc -c` の道具で見る。
3. **効き目は役割ごとの読む量で測る。** ソースの行数・ファイル数・保管量で「圧縮した」と言わない。報告は層ごとの KB、役割別の読む量、前回の見込みとの差。
4. **移す＝消す。** 移した先に同じ行があると機械で確かめたら、その日に元を消す。控えのフォルダは置かない。
5. **ハーネスに製品のコードを入れない。** 雛形は文書か 2KB までの断片。写しは製品のリポジトリへ。
6. **見込みは、1 つ実際に圧縮して測った比率で出す。** 足し算の見積もりだけで進めない。
7. **前後に照合を通す**（ID・表の行・数値・印）。通らなければ戻す。
8. **〔試作〕の根拠の文は置き場に。** 本には印と値だけ。圧縮は下位モデルで、実行中にやらない。
