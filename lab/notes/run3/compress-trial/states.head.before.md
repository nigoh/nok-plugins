# 状態の設計と、失敗・立ち直りの理論

画面がとりうる状態を洗い出して名前を付け、失敗しても入力を失わせず、取り返しのつかない操作だけを確かめる。そのための判断の表。

読む工程：情報設計（状態表）、ビジュアル・UI 設計、操作と言葉、テスト。

調査日：2026-11-14。印の意味：〔調査〕は公開されている指針で確かめたもの（末尾）。〔原理〕は広く知られた法則から導いたもの。〔目安〕はこのスキルが置いた数値で、実物で直す前提。〔試作〕は第3回の土台（つづり請求）で決めたもの。

## 使い方

画面ごとに E-01 の 5 軸を埋めて状態を決め（名前は E-02、扱わない物は E-03）、操作ごとに E-08 の事実（戻せるか・相手に届くか・お金に関わるか）から失敗の置き場所（E-06）を決める。理由は `E-08：請求書を送る・戻せない・相手にメールが届く → 窓で確かめる。「元に戻す」は付けない` の形で 1 行残す（表の見本は `_moved/states.design.md`）。待ちの見せ方は motion.md A-03 が正で、ここは「何を残し何を隠すか」だけ。

## 原理

| ID | 原理 | 言い換え |
| --- | --- | --- |
| EP-1 | 状態は軸ごとに 1 つ。軸どうしは重なってよい〔原理〕 | 「待ち」と「前のデータ」は別の軸 |
| EP-2 | 空っぽと読み込み中を取り違えさせない〔調査〕 | 読み込み中に「0件」と出さない。0 件は理由と次の一手を言う |
| EP-3 | 失敗は、何が起きたか・どう直すか・直す手段を、起きた所に置く〔調査〕 | 謝るだけにしない。見ていない人にも残す |
| EP-4 | 戻せる物は「元に戻す」で救い、戻せない物だけ前もって確かめる〔調査〕 | 窓は使いすぎると読まれない |
| EP-5 | 入力した物を機械の都合で失わせない〔調査〕 | 失敗・離れる・期限切れでも残す。同じ事を二度入れさせない |
| EP-6 | 同じ操作は 1 回しか効かない〔原理〕 | 連打・再試行・戻るで二重に起きない |

出どころ・検査（STATE-AXIS ほか）・設計書の書式（状態表・操作表）は `_moved/states.{sources,checks,design}.md`。人が見る：失敗と窓の文言の具体さ、通知の量、0 件の種類の区別、時間切れの警告、`stale` の時刻の文言。確かめていない物：〔目安〕の数値（再試行 2 回と 1・3 秒、3 回続けて失敗、2 分前、10 回／日、5 件、5 個）。「元に戻す」10 秒は第3回の土台（Toast）の値。
