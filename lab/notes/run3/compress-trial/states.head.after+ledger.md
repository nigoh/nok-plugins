# 状態の設計と、失敗・立ち直り

画面の状態を洗い出して名前を付け、失敗しても入力を失わせず、取り返しのつかない操作だけ確かめる。読む工程：情報設計（状態表）、UI 設計、操作と言葉、テスト。印の意味・判断の書き方は README。

待ちの見せ方は motion.md A-03 が正。ここは「何を残し何を隠すか」だけ。

## 原理

| ID | 原理 |
| --- | --- |
| EP-1 | 状態は軸ごとに 1 つ。軸どうしは重なってよい〔原理〕 |
| EP-2 | 空っぽと読み込み中を取り違えさせない〔調査〕 |
| EP-3 | 失敗は、何が起きたか・どう直すか・直す手段を、起きた所に置く〔調査〕 |
| EP-4 | 戻せる物は「元に戻す」で救い、戻せない物だけ前もって確かめる〔調査〕 |
| EP-5 | 入力した物を機械の都合で失わせない〔調査〕 |
| EP-6 | 同じ操作は 1 回しか効かない〔原理〕 |
states 〔目安〕：再試行 2 回と 1・3 秒、3 回続けて失敗、2 分前、10 回／日、5 件、5 個。「元に戻す」10 秒は第3回の土台（Toast）の値。
