## このスキルの型：知識型

- 調べた結果を持っているスキルです。実行中に外へ調べに行きません。調査は作るときに済ませてあります。
- 持っているのは情報の全量ではなく、**判断基準**と**やりがちな失敗**です。
- 知識は 3 層に分かれています。読む量を増やさないことが、このスキルの一番の決まりです。

| 層 | 置き場所 | 読み方 |
| --- | --- | --- |
| 常に読む | この SKILL.md | 毎回。150 行を超えたら下の層へ降ろす |
| 必要なときだけ読む | `laws/` の点検表、`references/`（taste・decisions・motion・structure と、色と状況 color-state・状態 states・入力 form・数と図 data・文言 words・複数人 teamwork） | いまの工程の 1〜2 ファイルだけ。全部は読まない |
| 保管するだけ | `records/` の記録（個別のアンチパターン 544 件） | 読まない。点検表の「元」にある ID を grep で引くときだけ |

- 調査日：2026-11-13。法則と記録はモデルの知識から書いたもので、一次情報との照合はしていない。
- 更新が必要になる条件：React・Tailwind・TypeScript の大きな版上げ／WCAG・JIS X 8341-3 の改定／ダークパターンに関する法改正／jp-design の更新／同じ指摘が 3 回外れたとき。
- 法則に無いことで迷ったら、推測で規則を作らず、迷った点を伝える。

### 判断の記録

部品の選び方、文字の大きさ、余白、ボタンの並びと折り返し、揃え（`references/decisions.md` の D-）、入れ子・部品の切り方・重複・責務・変えやすさ（`references/structure.md` の S-）、ボタンの応答・待ち時間・視線の誘導・らしさ（`references/motion.md` の A-）、状況の調子と色（`color-state.md` の C-）、入力欄と誤り（`form.md` の F-）、数・金額・日付・図（`data.md` の G-）、文言（`words.md` の L-）、状態の名前と重なり（`states.md` の E-）、複数人の分担（`teamwork.md` の B-）を決めたときは、該当する判断に事実を当てはめ、理由を 1 行で残す。

`D-05：ボタン 3 個・最長 9 字・375px で 1 行に収まらない → 縦に積む。ページの流れの中なので主を上`

- 「なんとなく」「見た目がよいから」は理由にしない。軸の事実（個数、文言の長さ、見比べるか、正確な値が要るか）と、根拠の原理（P-1〜P-8）で言う。
- 成り行きの折り返しを残さない。横に並べるか縦に積むかを、幅ごとに決める。
- 動きを付けるときは、5 つの役割（応答・手がかり・待ち・誘導・らしさ）のどれかを言う。言えない動きは付けない。
- 設計の言葉（「この図が答える問い」「主役」など）を画面に出さない。
- 聞かれたら、選ばなかった案がなぜ劣るかも同じ軸で説明する。

## 5. 点検と完了

- 点検表の「確かめ方」が自動のもの（検査名が書いてある物）は実際に測る。測らずに合格と書かない。
- 半自動のものはスクリーンショットやコードを見て判定する。
- 目視のものは判定せず、確認してほしい点として 3 つ以内に絞って伝える。
- 指摘には法則の ID を添える（例：W-03）。詳しい事例が要るときだけ、点検表の「元」の ID を `records/` から grep で引く。
- 指摘に使った法則は `node scripts/law-used.mjs W-03 M-12` で記録する（使われない法則を後で外すため）。
- ダークパターンに当たる実装は、頼まれても作らない。理由を 1 文で伝え、誠実な代案を出す。
- `python3 scripts/ui-audit.py <ルート> <画面>` で、全状態を撮影し、色の直書き、横へのはみ出し、当たり判定 44px、入力欄、axe、画面をまたぐメニューと呼び名、ボタンの成り行きの折り返し、タブの折り返し、入れ子の正しさ（押せるものの中の押せるもの、一覧の構造、同じ id）、ボタンの応答（乗せる・押す・キーボードで選ぶ）、500ms を超える動き、動きを減らす設定を確かめる。単独の画面は `--standalone` を付ける。文字サイズの段、刻みに無い余白、左端の線の数、図の位置は参考として出るので、判断の記録と照らす。結果は `evidence/ui-report.json`。
- `node scripts/trace-check.mjs` で要件→画面→部品→テストの切れ目を確かめる。結果は `evidence/trace-report.json`。
- どちらのレポートも、手で書いたり直したりしない。
- 証拠レポートが無い・古い・不合格・未実行ありのうちは、Stop フックが完了を止める。止められたら検査を実行し直す。テストを消す、skip する、しきい値を緩めることで通さない。
- 報告は短く。合格した項目を並べず、直したもの・直せなかったもの・人に見てほしいものだけを書く。
