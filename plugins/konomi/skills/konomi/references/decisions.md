# 判断の理論

部品・文字・余白・並びを、理由を言える形で決めるための表。読む工程：ビジュアル・UI 設計、操作と言葉。

調査日：2026-11-14。印：〔調査〕公開された指針で確認。〔原理〕広く知られた法則から導いた。〔目安〕このスキルの数値（実物で直す前提）。〔試作〕試作（第1・2回）で衝突や外れが出て決めた。

早見表は references/INDEX.md。

## 使い方

迷ったら該当 D- の「軸」に事実を当て、表で選び、理由を 1 行（事実→選んだ物）で残す。形の例は references/design-doc.md、検査の一覧は records/checks.md。
好み（DESIGN.md）は P-1〜P-8 に反しない範囲で優先。要件と食い違ったら理論が正（要件に見た目を書かない）。ただし要件の中身（全件の表、区分での切り替え）は要件が正。

## 原理

| ID | 原理 |
| --- | --- |
| P-1 | 見比べるものは同時に見せる（切り替えると前の内容を覚えていられない） |
| P-2 | 選択肢は見えているほうが選びやすく、多いほど時間がかかる（ヒックの法則） |
| P-3 | 大きく近い的ほど、速く正確に押せる（フィッツの法則） |
| P-4 | 近いものは仲間に、揃っているものは同列に見える（意図しない近さ・ずれは意図しない意味を生む） |
| P-5 | 差は、はっきり付けるか、付けないか（小さすぎる差は誤りに見える） |
| P-6 | 読みやすさは行の長さ・行間・文字の大きさで決まる |
| P-7 | 同じものは同じ形、違うものは違う形（同じ見た目なら同じ動きを期待される） |
| P-8 | 隠したものは、無いのと同じ（畳む・しまう・スワイプの先は、見なくても困らないものだけ） |

## D-01 内容を切り替える見せ方

根拠：P-1・P-2・P-3・P-7・P-8。軸：①見比べるか ②いくつあるか ③ラベルは短いか ④全員が全部読むか、一部の人が一部だけか ⑤順番があるか

| 条件 | 選ぶもの |
| --- | --- |
| 見比べる・両方を覚えて答える | 並べる（表、横並び、縦に続ける）。タブにしない〔調査〕 |
| 2〜5 個、同格、同時に 1 つだけ見ればよい、ラベルが短い | タブ（画面内の切り替え）。2〜3 個で値を選ぶ意味ならセグメント |
| 6 個以上、またはスマホでラベルが 1 行に収まらない | 縦の一覧で別画面へ、またはセレクト。タブを折り返さない〔調査：6 個が目安〕 |
| 一部の人が一部だけ読む補足（よくある質問、詳しい条件） | アコーディオン。お金・取り消し・期限に関わる答えは畳まない |
| 順番に進む | ステップ（現在地と全体数を示す）。タブにしない |
| 同じ種類で、並びに意味が薄く、全部見なくても困らない（写真、おすすめ） | スワイプで送る並び。個数と現在地、前後のボタンを付け、自動で動かさない |
| 要件が「区分で切り替える」と指定した | タブにする。節分けは区分の中（F-01）。部品名は要件でなくこの表で選ぶ〔試作〕 |
| 上のどれでも迷う | 全部を縦に並べる。短くできないか、削れないかを先に考える |

- タブは「画面内の表示の切り替え」と「別の場所への移動」を混ぜない。
- スワイプで送る並びに、主ボタンや必ず読ませる情報を入れない。

## D-02 1 つを選ばせる入力

根拠：P-2・P-4・P-7。軸：①選択肢の数 ②選んですぐ反映か、後で保存か ③選択肢を見比べるか

| 条件 | 選ぶもの |
| --- | --- |
| オンとオフの 2 択で、切り替えたらすぐ反映 | スイッチ |
| 2 択だが、送信・保存で確定する | ラジオかチェック。スイッチにしない |
| 2〜5 個 | ラジオ（縦）。短いラベルで横に収まるならセグメント |
| 6〜15 個 | セレクト。見比べるならラジオを縦に |
| 16 個以上 | 検索できる選択（入力して絞る） |
| 複数選べる絞り込み | チップ（折り返してよい）かチェック |

## D-03 数値の入力

根拠：P-2・P-3。軸：①正確な値が要るか ②範囲が決まっているか ③結果を見ながら探るか

| 条件 | 選ぶもの |
| --- | --- |
| 正確な値が要る（金額、数量、日数） | 数値の入力欄。中身（type・inputmode・autocomplete）は F-05〔調査〕 |
| おおよそでよく、動かしながら結果を見る（音量、明るさ、価格帯、図の操作） | スライダー。いまの値を必ず表示し、入力欄かボタンでも変えられるように〔調査〕 |
| 1〜10 くらいの小さな整数を増減する（人数、個数） | 増減ボタン（＋／−）つきの欄 |
| 範囲が広い、上限が無い、細かい刻みが要る | 数値の入力欄。スライダーにしない〔調査〕 |
| 選択肢が 2〜5 個の段階（弱・中・強） | ラジオかセグメント。スライダーにしない〔調査〕 |

- スライダーは指を離すときに値がずれやすい。スマホでは別の入れ方を必ず併設する。〔調査〕

## D-04 操作の出し方

根拠：P-2・P-3・P-4・P-5・P-7・P-8

| 条件 | 選ぶもの |
| --- | --- |
| その画面でいちばん大事な操作 | 主ボタン（塗り）。1 画面に 1 つ。比較や閲覧など主操作が無い画面には置かない〔試作〕 |
| 主の次に使う操作 | ふつうのボタン（枠） |
| 別の場所へ行くだけ | リンク。ボタンの形にしない |
| よく使い、意味が広く通じる絵がある（閉じる、検索、戻る） | アイコンのボタン。読み上げ名を付ける。通じにくい絵には言葉を添える |
| たまにしか使わない操作が 3 つ以上 | 「その他」のメニューにしまう |
| 取り返しのつかない操作 | 主ボタンから離し、色と言葉で区別する |

## D-05 ボタンの並びと折り返し

根拠：P-2・P-3・P-4・P-5・P-7。軸：①個数 ②最長の文言 ③その幅で 1 行に収まるか（各 44px 以上、間 8px 以上）

| 条件 | 決め方 |
| --- | --- |
| 全部が 1 行に収まる | 横。主の位置は全画面で同じ側 |
| 収まらない・2 個 | 縦に積み全幅。流れの中は主が上。窓・下の操作帯・入力画面は主が下（親指側）。順が幅で変わるなら `useMedia` で DOM ごと替える（S-10）〔試作〕 |
| 収まらない・3 個以上 | 主と副を残して縦、残りは「その他」へ |
| 1 つだけ 2 行になる | 文言を短く。無理なら全部縦。高さの違うボタンを並べない |
| チップ、タグ | 折り返してよい。行頭を揃え、行間と横の間を同じに |
| タブ、ステップ | 折り返さない。D-01 へ |

- 主の置き場所は F-10、文言の長さは L-03、窓・下の操作帯は「やめる」→主（DOM も同じ、S-10）、幅の組み替えは D-13。
- 成り行きの折り返しは使わない（最後の 1 個だけ落ちると仲間外れに見える）。幅ごとに横か縦かを決めて書く（境目は端末名でなく中身）。

## D-06 文字の大きさ

根拠：P-5・P-6・P-7。

| 条件 | 決め方 |
| --- | --- |
| 役割が同じ（同じ階層の見出し、同じ種類のラベル） | 同じ大きさ。画面や区画で変えない |
| 役割が違う | まず太さ・色（控えめな文字）・余白で分ける。足りないときだけ大きさ |
| 大きさを変える | 隣の段と比 1.125 以上あける。1px だけ違う段（13 と 14、15 と 16）を作らない。密度の高い画面は本文 14・見出し 16 太字（比 1.14）〔目安〕〔試作〕 |
| 段の数 | 1 画面で 4〜5 段まで。増やす前に既存の段で足りないか確かめる〔目安〕 |
| 小さくする | 補足（時刻・件数・単位）だけ。入力に要る説明・操作の文言は小さくしない。図の中の最小は D-12 |
| 行の高さ | 本文は文字の 1.5 倍以上（日本語は 1.7 前後）。文字が大きいほど比を詰める〔調査〕 |
| 強調 | 1 つの段落で 1 か所まで。太字・色・大きさを重ねない |

## D-07 余白（パディングとマージン）

根拠：P-3・P-4・P-5・P-7。

| 条件 | 決め方 |
| --- | --- |
| 余白の大小の順 | 部品の内側 ＜ 仲間どうし ＜ 別の仲間との間 ＜ セクションの間。逆転させない |
| 見出しの上下 | 上を広く、下を狭く（上は下の 2 倍以上）。見出しを説明する内容に近づける〔目安〕 |
| ラベルと入力欄 | ラベルは自分の欄に近く、前の欄から遠く |
| ボタンの内側 | 左右は上下の約 2 倍。文字サイズに比例（上下 0.5〜0.75em、左右 1〜1.5em）〔目安〕 |
| 面（カード）の内側 | 4 辺を同じに。中の部品どうしの間より広く |
| 同じ階層の繰り返し（一覧の行、カードの並び） | 全部同じ余白。1 か所だけ変えない |
| 値 | 好みの既定値の刻みだけ。刻みに無い値（10、14、18、20 など）を作らない |
| 差を付ける | 刻みで 1 段以上あける。違いが 4px 以下の「ほぼ同じ」余白を並べない |
| 幅が変わる | 狭い画面ではセクション間と面の内側を 1 段詰める。部品の内側は詰めない（押しやすさが落ちる） |

## D-08 揃え（インデントと左端）

根拠：P-1・P-4・P-6・P-7。

| 条件 | 決め方 |
| --- | --- |
| 1 つの区画の左端 | 揃える線は 1 本を基本に、多くて 3 本まで〔目安〕 |
| 字下げ | 親子（入れ子）を示すときだけ。飾りや区切りで下げない |
| アイコン付きの行と無しの行が混ざる | 文字の頭を揃える（無しの行はアイコンの幅だけ空ける） |
| 2 行に折り返す項目（箇条書き、アイコン付きの文、チェック欄） | 2 行目を 1 行目の文字の頭に揃える。記号の下へ回り込ませない |
| ラベルと値を横に並べる | ラベルの幅を揃え、値の頭を 1 本の線に。スマホで収まらなければ全部縦（一部だけ縦にしない） |
| 数値の列 | 右揃え、等幅の数字。単位は見出しへ |
| 文章 | 左揃え。中央揃えは 2 行以下の短い文だけ |
| 見出しと、その下の内容 | 左端を同じ線に。面（カード）の中は面の内側の線に揃える |

## D-09 文字の折り返し

根拠：P-4・P-6・P-8。

| 条件 | 決め方 |
| --- | --- |
| 見出しが 2 行以上になる | 行の長さをそろえる（`text-wrap: balance`）。最後の行に 1〜2 字だけ残さない |
| 数値と単位、敬称、日付と曜日 | 途中で折らない（`white-space: nowrap`） |
| ラベルと値 | 行をまたいで離さない。離れるなら縦に組み替える |
| ボタンの文言 | 折り返してよい（縦に伸びる）。途中で切って「…」にしない |
| 表のセル、一覧の項目名 | 折り返して全部見せる。省略するなら全文を見る手段を置く |
| 本文の 1 行 | 日本語は 30〜40 字。それを超える幅にしない〔目安〕 |

## D-10 情報の置き場所

根拠：P-1・P-4・P-8。

| 条件 | 決め方 |
| --- | --- |
| 判断や入力に要る | 常に見せる。操作の近くに置く |
| 一部の人だけが要る補足 | 畳む（D-01） |
| 操作の直前に知るべき注意（料金、取り消せないこと） | その操作のすぐ上。離れた注記にしない |
| 言葉の説明 | 本文に書く。ポインタを乗せたときだけ出る表示に、必要な情報を入れない |
| 詳しい中身が長い | 別画面。戻ったとき元の位置に戻れるように |

## D-11 一覧の形

図か数字か表かは G-01。数・金額・日付の書式は G-05・G-07。根拠：P-1・P-4。

| 条件 | 選ぶもの |
| --- | --- |
| 項目どうしを同じ軸で見比べる（数値、日付、状態） | 表。狭い画面では列の優先順位を決めて行に組み替える（D-13）。組み替えても role を手で補い、表として読み上げられるように〔試作〕 |
| 1 件ずつ読む、項目の長さがばらばら | リスト（行）。面にしない |
| 1 件が独立した単位で、絵や複数の操作を持つ | カード |
| 2〜4 件を細かく比べる | 横に並べた比較（同じ項目を同じ行に） |

## D-12 図と説明の順、図の中の扱い

根拠：P-1・P-3・P-4・P-6・P-8。軸：図の順、中の文字・凡例・操作・現在位置。

| 条件 | 決め方 |
| --- | --- |
| 図が主役 | 見出しの次に図。説明と凡例は後か横。スマホの最初の 1 画面に図の頭が入るように（D-14）〔試作〕 |
| 図の中の文字 | ラベルは 14px 以上、目盛り・補足は 12px 以上。収まらないラベルは HTML で重ねるか図の外へ。図を縮めて文字を小さくしない。折り返して 1 字だけ残るなら字数か段を減らす〔目安〕〔試作〕 |
| 凡例を作るか | 図の中に直接書けるなら作らない。作るなら図に接し、実際に使った線の種類・塗り・形だけ載せる。系列の色は C-11〔試作〕 |
| 図の要素を押せるようにするか | 押すと詳しい説明が出るなど意味があるときだけ。押せるなら当たり判定 44px 以上、読み上げ名に見えている文言を含める。細い棒や線は押せるようにせず、対応する一覧の行やボタンに操作を置く〔試作〕 |
| 時間の軸がある | 現在位置を線と「いま HH:MM」の札で示す。色だけにしない〔試作〕 |
| 図を並べて比べる | 同じ縮尺（実寸 1:1）。文字を守るために片方だけ縮めない。収まらなければ D-13〔試作〕 |
| 広い画面 | 図に幅を使う。小さいまま余白で囲まない〔試作〕 |
| 作り手の言葉 | 「この図が答える問い」など設計の言葉を画面に出さない（L-02）。図の見出しは読む人が知りたいことの名前に〔試作〕 |

## D-13 幅が変わるときの組み替え

根拠：P-1・P-4・P-6・P-7・P-8。軸：①何の並びか（ボタン、表、流れ図、時間割） ②最長の文言・最小の列幅 ③読む順 ④失いたくない意味（つながり、並行、現在位置）

| 条件 | 決め方 |
| --- | --- |
| 境目の幅 | 端末名でなく中身で決める。最長の文言か最小の列幅が収まらなくなる幅を部品ごとに書き、前後の幅で崩れないか見る〔試作〕 |
| 収まらない | 縮小で済ませない。組み替えるか、横に送るかを決める〔試作〕 |
| 表 → 行 | 列の優先順位を決め、主の列を行の頭に。各行にラベルを残す。role を手で補う（D-11） |
| 横の流れ図 → 縦の線図 | 段の順を保ち、つなぎ線は縦に。分岐は枝ごとの見出しで縦に並べ、実線・破線の意味と現在位置の印を残す〔試作〕 |
| 時間 × 場所の図 → 縦 | 並行を失わない。各枠に時刻と場所の札、同じ時間帯は 1 つの時刻見出しに〔試作〕 |
| 組み替えた後に選ぶ図 | 結果の説明は選んだ要素のすぐ近くに。画面の外・固定の表示にしない（D-10）〔試作〕 |
| 組み替えの前後 | 読む順と意味が変わらない。項目を落とさない |

## D-14 情報の順と、最初の 1 画面

根拠：P-3・P-4・P-8。軸：①いちばん見たい・やりたいこと ②利用者が何かする必要がある知らせがあるか ③説明を読まないと使えないか

| 条件 | 決め方 |
| --- | --- |
| 最初に置くもの | 主役を見出しの次に。スマホ幅の最初の 1 画面（高さ 812px 目安）に主役の頭が入る〔目安〕〔試作〕 |
| 並びの型 | 題名 → 説明 → 知らせ → 本体の定型をそのまま使わない。画面ごとに主役から順を決める〔試作〕 |
| 説明文 | 主役の後か横。使う前に要る 1〜2 行だけ前に置いてよい〔試作〕 |
| 知らせ（注意の枠） | 利用者が何かする必要があるときだけ先頭、その操作のすぐ上（D-10）。参考の知らせは関係する場所の後か近く |
| 主役に操作がある | 主操作を最初の 1 画面に入れる（D-04） |
| 最初の 1 画面に入らない | 説明・凡例・知らせを主役の下に回す |

出どころ：records/sources.md。〔目安〕は一次情報で未確認、〔試作〕は第2・3回の計測で決めた。
