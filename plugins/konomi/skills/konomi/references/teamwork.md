# 分業の決まり

複数の人・エージェントが同時に 1 つの製品の画面を作るときの、先に決める物・任せる物・守らせ方・合流のしかた。読む工程：実装の前（土台を作る人）と、画面を 1 枚ずつ受け持つとき。

調査日：2026-11-14。印：〔調査〕公開資料で確認（records/sources.md）。〔原理〕広い考え方から導いた。〔目安〕このスキルの数値。〔試作〕第3回（土台 1 人＋画面 10 人）の物。

早見表は references/INDEX.md。

## 使い方

2 人以上なら、最初の画面の前に B-01 を 1 人で決め切り、土台は B-06 の番人が通るまで完了にしない。足りない物は B-03 で報告し、合流で B-07 を行う。理由は 1 行（例：`B-03：札が 3 画面で要る・土台に無い → 仮置きして報告、合流で土台へ`）。手引き・完了点検表の型は references/design-doc.md、検査の一覧は records/checks.md。

## 原理

| ID | 原理 |
| --- | --- |
| BP-1 | 人の分け方が、製品の継ぎ目になる（コンウェイの法則。放っておくとメニューも呼び名も人の数だけ生まれる）〔調査〕 |
| BP-2 | つなぎ目を先に決め、中は任せる（画面の外は固定、中は担当が決める）〔原理〕 |
| BP-3 | 触ってよい場所は、名前 1 つで言える（「自分の画面のフォルダだけ」）〔調査〕 |
| BP-4 | 同じ決めごとは 1 か所。足りない物は報告して 1 か所へ上げる（並行すると他人の画面は見えない。重なりは報告で見つける）〔原理〕 |
| BP-5 | 守らせるのは文章でなく機械（手引きは忘れられる。約束は落ちるテストに）〔原理〕 |
| BP-6 | 部分が全部正しくても、並べると食い違う（合流後に、同じ物が同じ形か（P-7）を画面をまたいで測る）〔原理〕 |

## B-01 先に決める物と任せる物

根拠：BP-1・BP-2・BP-4。軸：①2 画面以上に出るか ②画面が違っても同じであるべきか

| 条件 | 決め方 |
| --- | --- |
| 全画面に同じ形で出る（メニュー、主操作の位置、戻り方） | 先に決める。`shell` に書く（W-29） |
| 呼び名、文の調子（です・ます）、避ける言い方、円と日付の書き方 | 先に決める。`terms` に使う語と避ける語を対で〔試作〕 |
| 画面の一覧、各画面の状態（固有も）、受け持つ要件 | 先に決める。担当は状態を足さない（W-07）〔試作〕 |
| 2 画面以上で使う部品・トークン・見本データ・状況→札の対応 | 先に作る。画面側で作らせない（S-04） |
| 画面をまたぐ窓（離れる窓・確かめの窓） | 1 度に決める（文言・ボタンの順・戻りの名前。戻りは「入力に戻る」）〔試作〕 |
| 1 画面の中だけの組み合わせ・並べ方・説明文・入力規則 | 各自に任せる |
| **最初から土台に入れる物**（入力画面・一覧の標準セット） | `useLeaveGuard`＋離れる窓、`nav.replace`、`useUrlParam`、全角→半角の直し、`paginate` と「押せない」、`fakeSave`、`save_failed`、全部品の `disabled`・`aria-describedby`、更新中・古い内容の文〔試作〕 |

## B-02 分ける単位

根拠：BP-1・BP-3

| 条件 | 選ぶもの |
| --- | --- |
| 要件が 1〜2 画面で完結し、画面に状態表がある | 画面ごと。1 人 1 画面 |
| 1 つの要件が 3 画面以上にまたがる | その画面の組を 1 人に |
| 層ごと（表示 1 人、取得 1 人） | 選ばない。1 画面の修正に全員が触る |

## B-03 触ってよい場所と、足りない物の手順

根拠：BP-3・BP-4

| 条件 | 決め方 |
| --- | --- |
| 触ってよい場所 | 自分の画面のフォルダと記録ファイルだけ。土台（ui・parts・app・data・トークン・screens.yaml）は書き換えない。基本の部品は作り直さず、足りない点を報告（M-04）〔試作〕 |
| 足りない物を見つけた | 直さず報告。1 行：何が・どの画面で・どう困る・仮に何を |
| 止まりたくない | 仮の物を自分のフォルダに置く。土台と同じ名前にしない |
| 仮の物が報告で 2 画面以上、かつ同じ決めごと（呼び名・状態・金額や日付の形・状況の札） | **合流のたびに**土台へ上げる。上げる人は 1 人。上げ損ねたまま次の合流に持ち越さない（S-03）〔試作〕 |
| 仮の物が 3 画面以上、見た目が似ているだけ | 同様に上げる。2 画面までは残す（S-02）〔目安〕 |

- 「3 か所目で切る」（S-02）は 1 人が見渡せるときの規則。並行では誰も 3 か所目を見ないので、報告を合流で数える。

## B-04 画面ファイルの決まった形

根拠：BP-2・BP-3

| 項目 | 決まり |
| --- | --- |
| 場所・登録 | `src/screens/<slug>/index.tsx`。ID と slug は screens.yaml のとおり。`screen`（ID・slug・題名・状態の一覧・部品）を 1 つ書き出す。自動で拾われるので一覧に足さない〔試作〕 |
| 状態の受け取り | 状態の名前を 1 つ受け取り、screens.yaml の状態を全部表示できる。無い名前は既定（W-07・M-09）〔試作〕 |
| 骨格への渡し方 | いちばん外は骨格の部品。画面の ID は文字のまま（照合が文字で探す）。状態と状態の一覧も渡す。題名・現在地・`main` は骨格が出す（S-10）〔試作〕 |
| 主操作・取り込み | 主操作は 1 つ、骨格の口へ（D-04）。置き場所は画面の種類で決まる（F-10）。取り込みは土台の入口からだけ（S-04）。絞り込み・ページ・タブは `nav.replace` で URL に（S-07）。画面の中だけの文言は画面フォルダの `copy.ts` 1 つ（名前はこれに統一）。画面の中だけの小部品・関数に CMP-ID・MOD-ID は付けない。2 画面以上で使う物は、画面に出る部品が CMP、出ない物（フック・関数）が MOD（S-02） |

## B-05 手引きの書き方

見出しの型は references/design-doc.md。BT- の一覧は records/checks.md。

- 禁止事項は 5〜8 個〔目安〕。機械が止める物に印を付ける（BP-5）。
- 部品の一覧は、書く前に実物と突き合わせる。古い手引きは、無い手引きより悪い。
- 画面ファイルの形（B-04）は写せる見本つきで。法則は ID で指す。

## B-06 機械の番人

根拠：BP-3・BP-5。軸：①破られると全画面に響くか ②ソースを読んで測れるか

| 条件 | 決め方 |
| --- | --- |
| ①②とも「はい」（層の向き、直書き、余白の刻み、時間、避ける言い方） | 番人にして土台に入れる（BT-01・03・06）。リンターで止められない任意値は、ソースの文字列を検査する（M-18）〔試作〕 |
| 土台の書き換え | 完了点からの変更ファイルを照合（BT-07） |
| 避ける言い方 | 日本語だけ検査（理由は L-02）（W-29）〔試作〕 |

- 番人は、見本の画面（通る）と悪い例（落ちる）の両方で試す。
- 番人の例外は理由を書く。3 つを超えたら層の切り方を見直す〔目安〕。

## B-07 合流の順と、確かめが落ちるとき

根拠：BP-4・BP-5・BP-6

| 条件 | 決め方 |
| --- | --- |
| 自分の場所の外の検査が落ちた | 自分のフォルダだけ通す。外の落ちは報告に 1 行。他人のテストを消さない・skip しない |
| 全体の照合が、未完成の画面で落ちる | 自分の分だけ通す。全体は合流後 |
| 合流の順 | ①報告を数え（「土台に足りない」の名前を集め、同じ名前が 2 画面から出たら一覧に）、B-03 に当たる物を土台へ上げ、仮の物を置き換える ②入口から奥へ、全体の検査 ③またいで見る〔目安〕 |

| またいで見る物 | 合格の線 | 測り方 |
| --- | --- | --- |
| 同じ物が同じ形 | 同じ請求書・同じ状況が、どの画面でも同じ札・金額・日付の形 | 半自動：同じデータの写しを並べる |
| 呼び名・主操作の位置 | 避ける語 0。同じ操作は同じ名前。主操作は 1 つで、同じ種類の画面では同じ置き場所（見る画面は見出しの右、入力画面は入力の末尾。F-10） | 自動（BT-05・06） |
| 行き来 | 戻る先の名前が来た画面の呼び名と同じ。行き止まり 0 | 半自動：主要な流れを 1 本 |
| 同じ決めごとの別実装 | 2 画面以上に同じ決めごとが出る物 0（土台に上げ済みを除く） | 半自動：画面フォルダを grep（`useLeaveGuard`・`replaceState`・`normalize('NFKC')`・`setTimeout`・`PAGE_SIZE`・時点の内容・同名ファイル）して画面数を数える |

## B-08 土台を後から変える

根拠：BP-3・BP-4・BP-5

| 条件 | 決め方 |
| --- | --- |
| 追加（部品・状態の語彙・トークンの段） | 土台の担当が足す。既存の名前は変えない。手引きにも足す |
| 名前・受け取る物・骨格・呼び名を変える | 全担当に 1 度に知らせ、土台の担当が使っている所を一括で直す。届く前は仮の物で進めてよい。変更の後は全画面の検査を通し直す |

## B-09 記録と、1 人で作るとき

根拠：BP-3・BP-6

| 条件 | 決め方 |
| --- | --- |
| 判断・気づき | 判断は各自の記録に 1 行ずつ。法則に無い気づきは報告へ（何が起きたか・防ぎたい失敗）。合流で 1 人が集める |
| 1 人 | 手引き・報告・記録の分離を省く。**省かない**：骨格・呼び名・状態表、BT-01・03・06、画面 6 枚以上なら「またいで見る」〔目安〕 |
