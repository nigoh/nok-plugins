# 構造の理論

入れ子・責務・重複・変えやすさを、理由を言える形で決め、デザインの段階で示すための表。読む工程：技術設計（部品に分ける前）と実装。

調査日：2026-11-14。印は decisions.md と同じ（〔調査〕〔原理〕〔目安〕〔試作〕）。出どころ・検査は records/sources.md・records/checks.md。

早見表は references/INDEX.md。

## 原理

| ID | 原理 |
| --- | --- |
| T-1 | 要素は意味で選び、入れ子は仕様が許す範囲で組む（見た目で選ばない。親が中に持てる物は仕様で決まる） |
| T-2 | 1 つの部品が変わる理由は 1 つ（構造・見た目・振る舞い・取得を混ぜると、どれを直しても全部が壊れうる。単一責任） |
| T-3 | 同じ「決めごと」は 1 か所に書く（消すべき重複は、似たコードでなく同じ決定が複数の場所にあること。DRY） |
| T-4 | 偶然似ているだけの物は、まとめない（早すぎる共通化は、重複より高くつくことがある） |
| T-5 | 部品は、自分が置かれる場所を知らない（外側の余白・幅・並びは親が決める） |
| T-6 | 変わりやすい物ほど外に出す（文言・色・項目・並び順・しきい値は、触る場所が 1 つに） |
| T-7 | 状態は、ありうる組み合わせだけを表せる形で持つ（真偽値の並びは「読込中かつエラー」を表せてしまう） |

## S-01 入れ子の正しさ

問い：この要素を、この要素の中に入れてよいか。

| してはいけない入れ子 | なぜ | 直し方 |
| --- | --- | --- |
| リンクの中のボタン、ボタンの中のリンク・入力欄・別のボタン | どちらが動くか決まらない。仕様が禁じる〔調査〕 | 兄弟として並べる。面全体を押せるようにしたいときは、見出しのリンクの当たり判定を面いっぱいに広げ、ほかの操作をその上に重ねる |
| 段落・見出し・ボタン・`span` の中の `div`・リスト・表・見出し | 文章の中身しか持てない〔調査〕 | 外側を `div` に、または内側を `span` に |
| `ul`・`ol` の直下に `li` 以外、`dl` の直下に `dt`・`dd`（と、組を包む `div`）以外。`dl` 直下で `div` と素の `dt`・`dd` を混ぜる | 仕様から外れ、一覧として読み上げられない〔調査〕 | 飾りは `li` や `dd` の中に。組を `div` で包むなら全部の組で |
| `label` の中の `label`・2 つ目の入力欄、`label` の中のリンクやボタン | 前者は仕様が禁じる〔調査〕。後者は押したときラベルの動きと衝突する〔原理〕。要確認：リンクの扱い | `for` と `id` で結び、操作は外に |
| 押せる `div`・`span`（クリックの処理だけ付けた物） | キーボードで届かず、役割が伝わらない | `button` か `a` に |
| 同じ `id` が 2 つ | ラベルと入力欄などの結びつきが壊れる | 一意に |

- 迷ったら、親が中に持てる物を仕様か MDN で確かめる。ブラウザが表示しても正しさの証明にならない。
- 要素の選び方の順：意味の合う要素（`button`、`nav`、`table`、`ul`、`label`）→ 無ければ `div`／`span` に役割を足す。逆にしない。

## S-02 部品に切るか

根拠：T-2・T-3・T-4。問い：ここを 1 つの部品として切り出すか。

| 条件 | 決め方 |
| --- | --- |
| 名前が付けられ、同じ理由で変わるまとまり | 切る |
| 自分だけの状態（開閉、入力中の値）を持つ | 切る |
| 見た目が似た物が 3 か所目に出てきた | 切る。2 か所までは待ってよい。ただし同じ決めごとと分かっているなら 2 か所目でもまとめる（S-03）〔目安〕 |
| 並行して作る（2 人以上） | 「3 か所目で切る」は 1 人が見渡せるときの規則。報告を合流で数えて切る（B-03）〔目安〕 |
| 1 回しか使わず、名前が「〜の上の部分」としか付かない | 切らない。その場に書く |
| 1 画面の中だけで使う小部品・関数 | その画面のフォルダに置く。CMP-ID も MOD-ID も付けない（2 画面以上で使う物だけ。画面内の部品は `data-part`）〔試作〕 |
| 2 画面以上で使う物の番号 | **CMP-nnn は「画面に出る部品」だけ**。コードに `data-cmp="CMP-nnn"` を必ず持つ。**画面に出ない共有の物（フック・関数・整形・取得の真似）は MOD-nnn**。screens.yaml の `modules:` に `file`・`exports`・`covers` を書き、テスト名に `[MOD-nnn]` を入れる。画面は土台の MOD を取り込み、同じ名前の関数を自分のフォルダに定義しない（trace-check MOD-SHADOWED）〔試作〕 |
| 1 つのファイルが、取得・整形・並べ方・見た目を全部やっている | 層で分ける（S-04） |

## S-03 まとめるか（重複の扱い）

問い：似ている 2 つを、1 つにまとめるか。

| 条件 | 決め方 | 根拠 |
| --- | --- | --- |
| 同じ決めごとから来ている（片方を変えたら、もう片方も必ず変える） | まとめる | T-3 |
| いま似ているだけで、変わる理由が別（別の画面、別の担当、別の要件） | まとめない。似たまま置く | T-4 |
| まとめた部品の引数が増え、真偽値の切り替えが 3 つを超えた | まとめすぎ。S-05 で直す〔目安〕 | T-4・T-7 |
| 値（色、余白、時間）が複数箇所に直書き | トークンにする | T-3 |
| 文言・項目・選択肢が、表示と検証とテストに別々に書かれている | 1 つの定義から引く | T-3 |

## S-04 責務の分け方

層は 7 つ。画面が、取得と部品を使う。部品の側は、組み合わせ → 基本 → トークンの一方向にし、部品は取得を呼ばない。整形（`lib`）は ui からも取得からも読めるが、`lib` は ui・取得を読まない。

| 層 | 知っていること | 知らないこと |
| --- | --- | --- |
| 画面 | どのデータが要るか（取得を呼ぶ）、どの部品をどこに置くか、URL と状態の対応 | 部品の中の見た目 |
| 取得 | 取得先、整形、キャッシュ、データの型 | どの画面が使うか、見た目 |
| 整形（`lib`：`lib/format`） | 数・日付・金額の整形、入力の読み（全角→半角の直し）。純粋な関数だけ | 画面、見た目、取得先 |
| 骨格（外枠・移動・呼び名） | 全画面で同じ外枠、メニューの項目と並び、主ボタンの位置、戻り方、画面と機能の呼び名（shell と terms。W-29） | どの画面の中身か、データ |
| 組み合わせの部品（一覧、フォーム、図） | 中の部品の並びと、そのまとまりの振る舞い | データの取り方、置かれる場所 |
| 基本の部品（ボタン、札、入力欄） | 自分の見た目と状態（押せない、読込中） | 業務の言葉・何のデータか、どの画面か |
| トークン | 値（色、余白、角、影、時間） | どこで使われるか |

- 基本の部品は外側の余白を自分で持たない（T-5）。間隔は親が `gap` で。
- 見た目の変化は、クラス名の付け替えでなく状態そのものに対して書く。順は、標準の疑似クラス（`:disabled`）→ 意味を持つ `aria-*`（`aria-expanded`）→ 見た目だけの状態は `data-*`。

## S-05 どこまで汎用にするか

根拠：T-2・T-4・T-7

| 条件 | 決め方 |
| --- | --- |
| 見た目の種類だけが違う（主・ふつう・消す） | 種類の引数 1 つ（列挙） |
| 中身が違う（アイコンが入る、説明が付く） | 中身を外から渡す（合成）。引数を増やさない |
| 振る舞いが違う | 別の部品にする |
| まだ使われていない種類・引数 | 作らない。要るときに足す |

## S-06 変えやすさを示す（変更シナリオ表）

問い：この構造は、あとから変えやすいと言えるか。

設計の段階で、起こりそうな変更を並べ、それぞれ「触る場所の数」を数える。1〜2 か所なら合格、3 か所以上なら構造を直す。〔試作〕

| 起こりそうな変更 | 触る場所（目標） |
| --- | --- |
| アクセントの色を変える | トークン 1 か所 |
| ボタンの角丸・高さを変える | トークンか、基本の部品 1 か所 |
| 文言を直す | その文言の定義 1 か所 |
| 一覧に項目（列）を 1 つ足す | 項目の定義 1 か所 |
| 状態を 1 つ足す（例：保留中） | 状態の定義 1 か所と、その表示 1 か所 |
| 選択肢を 1 つ足す | 選択肢の定義 1 か所 |
| 画面の並び順を替える | 画面 1 か所 |
| 組み替えの幅を変える | その部品 1 か所 |
| データの取得先が変わる | 取得の層 1 か所（画面は変えない） |
| 暗い画面に対応する | 役の名前の対応 1 か所（値で済まない画像などは別。要確認） |

- 表は題材に合わせて実際に起こりそうな変更を 8〜10 個。テストと型も数える。**2 件以上を実際に変え、触ったファイルを数え、「実際」の列を足して書く**（目標だけの表は完了にしない）。

## S-07 状態の持ち方

根拠：T-3・T-7

| 条件 | 決め方 |
| --- | --- |
| 同じ軸で同時に 1 つだけの状態 | 列挙 1 つ（`default`/`loading`/`error`）。真偽値を並べない。独立な物（開閉と無効）は別々。軸をまたぐ重なりは名前を付けた 1 値（`refreshing`・`stale`、E-04） |
| 人に見せたい・戻ってきたい状態（タブ、絞り込み、ページ） | URL。戻る・共有・再読み込みで同じ画面 |
| サーバーにある値 | 取得の層（キャッシュも）。画面の状態に写さない |
| ほかの値から計算できる物（件数、合計、選択中か） | 持たない。その場で計算 |
| 表示 | 状態から一意に決まる形 |

## S-08 CSS の構造

根拠：T-3・T-5・T-6

| 条件 | 決め方 |
| --- | --- |
| 値 | トークン 3 段：もとの値（色見本）→ 役の名前（`bg`、`ai`）→ 部品の値（`button-height`）。部品は役の名前と部品の値だけ使い、もとの値を直接使わない |
| 名前 | 見た目でなく役で付ける（`.blue-button` でなく `.button[data-variant="primary"]`） |
| 詳細度 | 低くそろえる。`!important`、`id` セレクタ、深い入れ子で打ち消さない。上書きの順は `@layer`（要確認：対応）か読み込み順 |
| 並び（レイアウト）と見た目 | 分ける。並びは親、見た目は部品 |
| 部品の組み替え（狭いと縦に、など） | 部品が置かれた枠の幅で決める（コンテナクエリ。対応ブラウザは要確認）。画面幅（メディアクエリ）は画面の層だけ |
| 数字 | 理由の無い数字（`top: 37px`、`z-index: 9999`）を置かない。重なりは段のトークンに |
| 同じ宣言のかたまりが 3 回以上 | 部品かトークンにする〔目安〕 |

## S-09 部品の公開する面（引数・上書き・テスト）

根拠：S-04・T-2・T-3・T-5。問い：外から何を受け取り、どこまで上書きを許すか。

| 条件 | 決め方 |
| --- | --- |
| 受け取る物 | 基本の部品は表示に使う値だけ。業務の言葉（予約、顧客）は上の層で `tone` などに直して渡す |
| 標準の属性 | `button`・`input` などを包む部品は、標準の属性（`disabled`、`aria-*`）を残りの引数として中の要素に渡す |
| 見た目の上書き | 口は種類（列挙）・トークン・名前を付けたカスタムプロパティに絞る。呼び出し側の `class`・`style` は外側の配置だけ |
| テスト | 役（role）・ラベル・文言で見つけられる。内部のクラス名に頼るなら面が足りない |

## S-10 順序と読み上げの木

根拠：T-1。問い：見た目の順と、DOM の順（読み上げ・Tab の順）は同じか。

| 条件 | 決め方 |
| --- | --- |
| 並べ替え | 見た目の順は DOM の順で入れ替える。`order`・`row-reverse`・grid の配置だけだと、読み上げと Tab の順は元のままでずれる |
| 置き場所が幅で変わる（主操作が狭い幅では下、広い幅では見出しの右） | CSS の `order` でなく `useMedia` で DOM ごと替える。`matchMedia` が無い環境（テスト）では狭い側を既定に。D-05 の積む順（やめる→主）も DOM で同じに〔試作〕 |
| 見出し・ランドマーク | 階層で段を選び、段を飛ばさない。`main` は見える状態で 1 つ、`nav` が複数なら `aria-label` で区別。`h1` は 1 つにそろえる（複数も書けるが段にならない。要確認） |
| 名前 | 押せる物・入力欄・図・表に名前がある。見える文字と読み上げの名前を一致させる |

〔目安〕の数値（3 か所目で切る、真偽値 3 つまで）は一次情報で未確認。
