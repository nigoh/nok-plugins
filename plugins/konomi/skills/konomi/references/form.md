# フォーム（入力）の理論

入力画面を決める表。何を聞き、いつ確かめ、誤りをどう出し、日本の値（住所・電話・金額・和暦）をどう受け、送ったあとどうするか。D-02（1 つを選ぶ入力）・D-03（数値の入力の選び方）は ID で指す。

読む工程：情報設計、ビジュアル・UI 設計、操作と言葉、実装。早見表は references/INDEX.md。
印：〔調査〕指針で確認／〔原理〕法則から導出／〔目安〕このスキルの値（実物で直す）／〔試作〕試作で決定。出どころ・検査（FC-01〜11）は records/sources.md・records/checks.md、設計書の書式（欄の表と流れの 3 行）は references/design-doc.md。〔目安〕の確かめていない物も records/sources.md。

迷ったら判断（F-01〜）の「軸」に事実を当てる。理由は `F-04：必須 6 欄を空で送った・誤り 6 件 → 先頭に一覧、フォーカスは最初の誤り欄、各欄の直下にも同じ文` の形で 1 行残す。

## 原理

| ID | 原理 |
| --- | --- |
| FP-1 | 同じ作業で、一度聞いたことは二度聞かない〔調査〕 |
| FP-2 | 聞くのは、無いと先へ進めない物だけ〔調査〕 |
| FP-3 | 規則と例は、入れる前に見える所に〔調査〕 |
| FP-4 | 誤りは、欄の近くに、言葉で、直し方つきで〔調査〕 |
| FP-5 | 人が書いた物を、機械が黙って書き換えない。自動の値は、人が直した瞬間から手を引く |

## F-01 1 画面にまとめるか、段階に分けるか

根拠：FP-2・FP-7・I-05・W-05・taste.md。軸：①項目数 ②意味の塊の数 ③前の答えで次の項目が変わるか ④途中でやめる前提か ⑤お金・取り消し・相手への通知に関わるか

| 条件 | 選ぶもの |
| --- | --- |
| 項目 8 個以下・塊 1 つ | 1 画面。節の見出しも要らない〔目安〕 |
| 項目 9〜20 個・塊 3 つ以内 | 1 画面に節（見出し）で分ける。節は面にしない〔目安〕 |
| 21 個以上、塊 4 つ以上、または分岐あり | 段階（2〜5 個）。現在地と全体数（分岐後の実数）を出す〔目安〕 |
| 要件が「区分で切り替える」と指定している（設定画面の区分） | 区分は D-01 の切り替え（タブ）。節分けは区分の中で、項目数はその区分ごとに数える。要件を正にする〔試作〕 |
| 途中でやめる前提 | 段階。入力を残し、次は続きから（E-10） |
| お金が動く・相手に通知が飛ぶ・取り消せない | 送る前に内容を見せる確認を別に置く（E-08） |

- 1 問 1 画面は初めて来る人向け。毎日使う業務は関連する欄をまとめてよい。進捗表示の前に、順と数を直す〔調査〕。

## F-02 項目の順・区切り・列数

根拠：FP-2・P-4。軸：①手元の資料で見る順 ②欄の中身の長さ ③関連する欄が 1 つの値を作るか

| 条件 | 決め方 |
| --- | --- |
| 順 | 手元の資料で見る順（宛先→日付→明細→合計）。調べないと書けない欄は後ろ |
| 列 | 基本は 1 列。2 列は、1 つの値を作る組（数量・単価）だけ、768px 以上、1 行 3 欄以内〔目安〕。ラベルを欄の左に置く横組はしない |
| 欄の幅 | 中身の長さに合わせる。郵便番号は約 10 字、電話は約 16 字、金額は約 12 字、住所・メールは全幅（上限 36rem）〔調査〕〔目安〕 |

## F-03 ラベル・必須と任意・補足文・例

根拠：I-01・I-02・I-21・FP-2。軸：①必須の数と全体の数 ②説明の種類（規則・例・理由）と長さ

| 条件 | 決め方 |
| --- | --- |
| ラベル | 欄の上、左揃え、常に見える。短い名詞（12 字以内〔目安〕）、「：」なし。単位と税の区別も書く（「単価（税抜）」）〔調査〕 |
| 必須が全体の半分より少ない | 必須の欄に「必須」 |
| 任意が全体の半分以下 | 任意の欄に「任意」（必須に印なし）〔目安〕 |
| 必須にしてよい欄 | 無いと送れない理由を 1 行で言える欄だけ。全部必須なら印は付けず、先頭に「すべて入力してください」〔調査〕 |
| 規則・例・理由 | 補足文。ラベルの下・欄の上、常時、14px 以上、4.5:1。例はそのまま入れられる値（「例：060-0042」）。理由は自明でない欄だけ〔調査〕 |
| プレースホルダー | 使わない。許すのは、ラベルを別に持つ検索欄の言い換え 1 つだけ〔調査〕 |

## F-04 確かめる時機と、誤りの出し方

根拠：FP-4・I-03・I-22・REQ-009。軸：①誤りの種類（空欄／形式／欄どうし／サーバーでないと分からない）②送った時の件数。欄ごとの出し方はここが正（E-06・L-06 は指す）。

| 条件 | 決め方 |
| --- | --- |
| 入力中 | 誤りを出さない。出してよいのは、パスワードの条件、残り字数、合計〔調査〕 |
| 形式の誤り | 欄を離れた時に、欄の直下へ。直した瞬間に消す〔調査〕 |
| 空欄の必須 | 離れた時には出さない（Tab で通っただけで叱らない）。送る時に出す〔目安〕 |
| 出し方 | 欄の直下に絵と文、枠も変える。文は「何が起きたか＋どう直すか」。「入力に誤りがあります」だけにしない〔調査〕 |
| 送った時に 2 件以上 | 先頭に一覧（各行は欄へのリンク、文は欄と同じ）を `role=alert` で。フォーカスは一覧に移さない。1 件なら一覧なし〔調査〕 |
| 移動 | 最初の誤り欄へフォーカス。揺らさない。入力値は消さない |

## F-05 欄の形（type・inputmode・autocomplete）

根拠：I-04・I-07・I-09・I-10・I-11・D-03。軸：①値の種類 ②その値は利用者本人の情報か（自社か、取引先か）

| 値 | 決め方 |
| --- | --- |
| 氏名・会社名・住所 | `type=text`、`spellcheck=false`。本人の情報なら `autocomplete`〔調査〕 |
| メール・電話 | `type=email`／`type=tel` と `autocomplete`。前後の空白は黙って除く。電話は 1 欄 |
| 郵便番号 | `type=text`、`inputmode=numeric`、`autocomplete=postal-code`〔調査〕 |
| 金額・数量 | `type=text`＋`inputmode=numeric`。`type=number` にしない。小数がありうる物（数量 1.5 など）は `inputmode=decimal`。負がありうる値（差額）は `inputmode` を付けない。右寄せ、等幅〔調査〕 |
| 単位（円） | 欄の外か後ろ、ラベルにも書く（読み上げは読まない）。「円」を打たれても誤りにしない〔調査〕 |
| 他人の情報（取引先の住所・担当者） | `autocomplete` を付けない（本人の情報で埋まるのを避ける）〔調査〕〔原理〕 |

- 文字は 16px 以上、高さ 44px（I-10・I-11）。変換確定の Enter で送らない（I-09）。

## F-06 日本の値の受け方

根拠：FP-5・FP-6・I-06・I-07・I-08・D-03・M-33・T-15。軸：①値の種類 ②直すと意味が変わるか（全角数字→半角は変わらない。半角カナ→全角・旧字体は変わりうる）

| 値 | 受ける／直す時機と見せ方 |
| --- | --- |
| 数字・ハイフン・空白 | 全角も、ハイフン（－ ‐ ー −）も受ける。離れた時に半角へ直し、その欄直下の補足行に「半角にそろえました」（polite）。短い知らせ・先頭の枠には出さない。打つ間は書き換えない〔目安〕 |
| 意味が変わる直し | 欄は書き換えず、送る時か確認画面で見せて直せる〔調査〕 |
| 氏名・ふりがな・法人名 | 姓・名とふりがなは別欄。ふりがなは保存の字種に合わせる（ひらがな固定にしない）。読みの推測は空のときだけ。法人名は「株式会社」込みで 1 欄 |
| 郵便番号・電話 | 7 桁で住所を引く。補完は空の欄だけ。複数は選ばせ、当たらない・時間切れは「住所は手で入れられます」。番地・建物は別欄。電話は保存を数字だけに |
| 金額 | カンマ・「円」・全角を受ける。離れた時に桁区切り（G-05）。打ちながら整形しない（カーソルが飛ぶ） |
| 日付 | 1 欄に打て、選択でも入れる。「2026/11/30」「11月30日」「令和8年11月30日」「R8.11.30」を受け、離れた時に G-07 の長い形で見せる。休日の期限は誤りにせず「土曜日です」と知らせる。生年月日は年・月・日の 3 欄〔原理〕 |
| 和暦 | 既定は西暦。和暦は役所の様式に合わせる欄だけ（G-07）。元年は 1 年。改元の日（平成31年4月30日／令和元年5月1日）を試す（T-02）。保存は暦日 |

- デジタル庁は自動変換を送信時か確認画面に勧める。数字だけ離れた時に直すのは、計算に使う値の画面の判断〔調査〕。

## F-07 初期値と自動計算

根拠：FP-1・FP-5・REQ-004。軸：①値の出どころ（既定／他の欄から計算／前の入力）②人が直したか

| 条件 | 決め方 |
| --- | --- |
| 大多数（目安 8 割以上）が同じ値 | 初期値を入れ、出どころを欄の下に書く（「取引先の支払条件から入れました」）〔目安〕 |
| 人が直した欄 | 以後の自動計算で書き換えない。近くに「自動に戻す」。欄ごとに「人が直したか」を持つ |
| 元の欄が変わった | 直していない欄だけ更新し、欄の近くで知らせる（polite） |
| 計算結果（合計など） | 入力欄にせず値の表示。変更のたびに更新 |

## F-08 くり返す行（明細）

根拠：P-1・D-04・D-13・W-12。軸：①1 行の欄数 ②行数の上限 ③並びに意味があるか（印字順）

| 条件 | 決め方 |
| --- | --- |
| 1 行 3 欄以下・768px 以上〔目安〕 | 列見出しのある行 |
| 4 欄以上、またはスマホ | 行ごとに縦に積み「明細1」と番号、区切り線で分ける（面にしない） |
| 追加 | 行の下に副のボタン「明細を足す」。足した行の最初の欄へフォーカス |
| 削除 | 読み上げ名に行を含める（「明細2を消す」）。確認の窓でなく数秒の「元に戻す」。最後の 1 行はボタンを出さない |
| 並びに意味がある | 「上へ」「下へ」のボタン（44px）。ドラッグだけにしない（WCAG 2.5.7）。意味が無ければ並べ替えを作らない〔原理〕 |

## F-09 下書きの保存と、離れる時の確かめ

根拠：FP-7・I-23・W-12・W-26。離れる時の確かめ（文言と出す条件）はここが正（L-05 は指す）。軸：①入力にかかる時間 ②業務に下書きの状態があるか ③未保存の変更があるか

| 条件 | 決め方 |
| --- | --- |
| 3 分以内・下書きの状態が無い（取引先） | 自動保存しない。未保存を画面に示し、離れる時に確かめる〔目安〕 |
| 下書きの状態がある（請求書） | サーバーの下書きは「下書きを保存」でだけ作る（自動で一覧に増やさない）。入力中の控えは端末の中に残し、送れたら消す。口座などは入れない〔原理〕 |
| 離れる（画面内の移動）で未保存あり | 窓で「保存して離れる」（主）「保存せず離れる」「入力に戻る」（窓を閉じて入力へ戻る副。戻りのリンクや L-03 の「やめる」と取り違えない）。空のまま・保存済み・変更が無い段階から戻るときは窓を出さない |
| ブラウザの戻る・タブを閉じる | 止められない（beforeunload のみ）。守るのは入力中の控え（上の行）〔試作〕 |

> 離れる時の確かめは骨格が持つ（画面は「変更があるか」を渡すだけ）。`?state=confirming` でこの窓を見せる口も骨格に用意する。F-01：要件が「途中でやめても続きから」を求めるなら、項目が少なくても段階に分ける〔試作〕。

## F-10 送る・保存のボタンと、送ったあと

根拠：S-10・I-10・D-05・V-12・W-06・W-09・W-10・W-22・W-27・M-32。軸：①入力の高さ（スマホで 1 画面に入るか）②結果（全部成功／全部失敗／一部失敗）

| 条件 | 決め方 |
| --- | --- |
| 置き場所（768px 以上） | 入力の末尾の右。「やめる」は主の左。見出しの右には置かない（欄より先に Tab が届く）。見る画面・一覧は見出しの右〔試作〕 |
| 置き場所（768px 未満） | 下に固定。順は「やめる」→主（主が親指側）。DOM も同じ順 |
| 押せなくするか | 必須が空でも押せる。押したら誤りを出す。押せなくするのは送っている最中と、条件が足りない時（理由を隣に） |
| 送っている最中 | 押したボタンだけ処理中（「送っています」）。欄は変更不可。二重送信は E-09 |
| 全部成功 | 結果が見える画面へ移り、短い知らせ（「請求書を送りました」）。戻っても再送しない |
| 全部失敗 | 入力を残し元の画面で再送。欄が分かれば欄に、分からなければ先頭の知らせ枠に。送付が起きていなければそう書く。置き場所は E-06、再試行と「送れたか分からない」は E-07 が正 |
| 一部失敗 | 成功と失敗を分けて言い、失敗だけ残して再試行。E-06 が正 |

## F-11 編集と新規、読み取り専用と無効

根拠：P-7・I-16・FP-5・V-12・W-10。軸：①新規か編集か ②その値は今変えてよいか ③変えられないなら見せる意味があるか

| 条件 | 決め方 |
| --- | --- |
| 新規と編集 | 欄・順・ラベル・誤りの文は同じ部品。変えるのは見出し（「取引先の登録」「取引先の編集」）、主ボタン（「登録する」「保存する」）、戻り先、初期値だけ。編集で開いた時、保存された値を自動計算で書き換えない |
| 見る・写す必要がある（請求書番号、合計） | 読み取り専用。フォーカスでき、送信に含まれる。近くに「編集不可」〔調査〕 |
| 今は使えない（条件を満たさない） | 無効。フォーカスされず送信されない。理由を欄の近くに。値が大事なら読み取り専用 |
| 送ったあとは直すと相手と食い違う（送付済みの請求書） | 読み取り専用にし「送った請求書は直せません。取り消して作り直してください」〔原理〕 |

## F-12 チェック・ラジオ・スイッチの当たり判定 44px

根拠：D-02・I-13・M-31。

| 条件 | 決め方 |
| --- | --- |
| 作り方 | `<label>`（最小の高さ 44px）の中に 44px 四方の入れ物。その中に `opacity:0` の本物の `<input>` を `absolute inset-0 size-full` で重ね、見た目の箱（20px、スイッチは 44×24px）は別の要素。ラベルの文字も同じ `<label>` に入れる〔調査：44×44 CSS px〕〔試作〕 |
| 擬似要素を使わない理由 | `input` は `::after` を持てず、ボタンのように広げられない（taste.md の方法は使えない）〔試作〕 |
| ラジオ・スイッチ・禁止 | 同じ作り。隣の 44px は重ねない。スイッチは `role=switch`。フォーカスの輪は見た目の箱に。`display:none` は使わない（フォーカスと読み上げが消える） |
