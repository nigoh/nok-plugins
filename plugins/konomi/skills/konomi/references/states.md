# 状態の設計と、失敗・立ち直りの理論

画面の状態を洗い出して名前を付け、失敗しても入力を失わせず、取り返しのつかない操作だけ確かめる。

読む工程：情報設計（状態表）、ビジュアル・UI 設計、操作と言葉、テスト。早見表は references/INDEX.md。
印：〔調査〕指針で確認／〔原理〕法則から導出／〔目安〕このスキルの値（実物で直す）／〔試作〕第3回の土台で決定。出どころ・検査（STATE-AXIS ほか）は records/sources.md・records/checks.md、設計書の書式（状態表・操作表）は references/design-doc.md。〔目安〕の確かめていない物も records/sources.md。

画面ごとに E-01 の 5 軸を埋めて状態を決め（名前は E-02、扱わない物は E-03）、操作ごとに E-08 の事実（戻せるか・相手に届くか・お金に関わるか）から失敗の置き場所（E-06）を決める。理由は `E-08：請求書を送る・戻せない・相手にメールが届く → 窓で確かめる。「元に戻す」は付けない` の形で 1 行残す。待ちの見せ方は motion.md A-03 が正で、ここは「何を残し何を隠すか」だけ。

## 原理

| ID | 原理 |
| --- | --- |
| EP-1 | 状態は軸ごとに 1 つ。軸どうしは重なってよい〔原理〕 |
| EP-2 | 空っぽと読み込み中を取り違えさせない〔調査〕 |
| EP-3 | 失敗は、何が起きたか・どう直すか・直す手段を、起きた所に置く〔調査〕 |
| EP-4 | 戻せる物は「元に戻す」で救い、戻せない物だけ前もって確かめる〔調査〕 |
| EP-5 | 入力した物を機械の都合で失わせない〔調査〕 |
| EP-6 | 同じ操作は 1 回しか効かない〔原理〕 |

## E-01 状態の洗い出し

問い：この画面にどんな状態があるか。軸：画面の事実（件数の上限、通信の有無、入力欄、URL の id、役割の数）

| 軸 | 値の候補 | 「ある」と決める条件 |
| --- | --- | --- |
| データの量 | 0／1／ふつう／多い／多すぎる | 0：一覧・集計がある。1：「1件」で崩れる文言や図がある。多い：21 件以上（20 件ごとのページ送り、W-15）。多すぎる：上限（請求書 1,000・取引先 200・明細 50 行）か最長の文字（取引先名 60 字）〔試作〕 |
| 時間 | 待ち／途中／終わり | 待ち：通信がある。途中：一部が先に届く、または流れが 2 段以上。終わり：流れの最後がある |
| 成否 | 成功／失敗／一部だけ成功 | 失敗：通信か保存がある。一部：1 操作で 2 件以上を処理する |
| 人 | 初回／権限なし／見つからない／時間切れ（`session_expired`） | 初回：0 件で設定が未完了の人がいる。権限なし：役割が 2 つ以上。見つからない：URL に id がある。時間切れ：ログイン・下書き・リンクに有効期間がある（状況の「有効期間切れ」、C-02、データの値とは別物） |
| 入力 | 未入力／誤り／確かめ中／送っている最中 | 入力欄がある。確かめ中：窓か補完など検査の待ちがある。送っている最中：送る・保存・書き出しがある |

- 5 軸 × 全値の表を画面ごとに書き、各セルを「ある（名前）」「ほかに含む」「ない（E-03）」で埋める。空欄を残さない。「ある」状態は `?state=<名前>` で 1 つずつ出し、テスト名に `[SCR-004:overdue]` を入れる。

## E-02 状態の名前

問い：この状態を何と呼ぶか。共通の語に足すか。

| 条件 | 決め方 |
| --- | --- |
| 共通の語彙にある | その語。画面ごとに言い換えない（P-7） |
| 3 画面以上で起こる | 共通の語に足す。足す場所は語彙表と trace-check の 2 か所。足すのは土台の担当（B-08） |
| 保存・送る・取り消す・記録の通信が失敗した | すべて `save_failed`。何の操作かは文言（「請求書を送れませんでした」）。入力は残し、押した所の近くに role=alert＋もう一度（E-06・E-07）。操作ごとに語を分けない |
| 画面の一部分の状態 | `部位_共通の語`（`zip_error`、`candidates_empty`） |
| 請求書・入金の状況（データの値） | `status_`＋英語（`status_overdue`）。terms の status と同じ語 |
| 流れの段／入口の違い | `step_2`／`mode_edit`。小文字・下線・英語 1〜2 語。画面名や進行形を入れない |
| 押したボタンだけ処理中で見え方が同じ | すべて `saving`。何をしているかは文言（「請求書を送っています」） |

`部位_共通語`・`step_n`・`mode_*`・`status_*` の形は共通の語彙として自動で通り、`extra_states` に書かなくてよい（trace-check が許す）。

**足す共通の語（10 個）**：`filtered_empty`、`invalid`、`saving`、`done`（流れの終わり）、`resumed`（途中の続き）、`conflict`（別の人が先に更新）、`session_expired`（ログインなどの時間切れ。状況の「有効期間切れ」と区別するため `expired` にしない）、`save_failed`（保存・送る・取り消す・記録の失敗）、`refreshing`（前のデータを見せて更新中）、`stale`（更新できず前のデータを見せている）。`partial`（一部だけ成功）は E-04 の名前。

土台の旧名（sending・exporting→`saving`、draft・overdue・paid・diff→`status_*`、step2→`step_2`、zip_multi→`zip_many`）は次に作り直す回に改名。それまでは `extra_states` に寄せ先を注記〔試作〕。

## E-03 「要らない」と言える条件（none）

問い：この状態を扱わないと書いてよいか。

| 条件 | 書き方 |
| --- | --- |
| 数えられる上限がある | `many: "担当者は最大 5 名"` |
| 構造で起こらない | `empty: "請求書は必ず明細を 1 行以上持つ"` |
| 要件で決まっている | `forbidden: "全員が同じ権限（REQ-011）"`。理由は要件 1 か所に集め、画面は ID で指す |
| 通信が無い画面だけ | `loading`・`error`・`save_failed` を none にできる。通信がある画面は不可（EP-2） |
| 更新・流れが無い | `refreshing`・`stale`：表示中に再読み込み・並べ替え・ページ送りが無い（「データは開いた時の 1 回だけ読む」）。`partial`：1 操作で処理するのは 1 件だけ。`done`：流れの終わりが無い単発の画面。理由に数字か「1 回だけ」「1 件だけ」を書く |

- 理由は、数字・「必ず」「固定」・REQ の ID のどれかを含む。「不要」「該当なし」「起きない」「あとで」だけは理由にならない。
- 前提が崩れる変更（役割を分ける、上限を上げる）は、none を states に戻すと変更シナリオ表（S-06）に書く。

## E-04 状態の重なりと、待ちの中で残すもの

問い：2 つが同時に起きるとき、何を見せ、何を止めるか。軸：①前のデータがあるか ②その数字で人が確定する（お金・番号・期限）か ③「HH:MM 時点」と言えるか

| 重なり | 名前 | 残す | 隠す・止める |
| --- | --- | --- | --- |
| 待ち＋前のデータ（並べ替え・ページ送り・再読み込み） | `refreshing` | 前のデータ、見出し、主操作の位置。「更新しています」（role=status） | 骨組みは出さない。止めるのは確定する操作と、並べ替え・ページ送り（読み込みの重なりを避ける例外）だけ |
| 待ち＋データ無し（初回） | `loading` | 見出し、主操作の位置 | データの部分だけ骨組み（A-03）。0 件の表示は出さない |
| 失敗＋前のデータ | `stale` | 前のデータ。「HH:MM 時点の内容です。更新できませんでした」とやり直し | ②の操作（送る・記録）は押せなくして理由を書く。古い金額で確定させない |
| 失敗＋データ無し | `error` | 見出し | データの部分を失敗の表示に |
| 一部だけ成功 | `partial` | 成功した分 | 失敗した分を分け、理由と再試行を付ける |

- **更新中（`refreshing`）・古い内容（`stale`）のときは、確定する操作（送る・記録・取り消す）だけ止め、行を開く・詳細を見る・戻るなど開く・見るだけの操作は止めない。**止めたら理由を近くに書く〔試作〕。
- `?state=` は名前を 1 つだけ受ける。重なりは名前を付けて states に書く（S-07 の「同時に 1 つ」は軸の中の話）。

## E-05 0 件の種類

問い：0 件に何を書き、次に何を出すか。軸：①条件（絞り込み・期間・探す語）がかかっているか ②その画面で作られたことがあるか ③直前に最後の 1 件を処理したか。文の型は L-07。

| 条件 | 種類 | 書くこと・次の一手 |
| --- | --- | --- |
| 条件なし・作られたことが無い | 初回（`empty`） | 何が入る場所かを 1 文。作る導線は文と文中のリンクで（「最初の請求書を作る」）。上部（見出しの右）に主ボタンがあるなら、0 件の表示に同じ名前のボタンを重ねない（主は 1 つ、D-04）。上部に主ボタンが無い画面だけ、案内の側のボタンを主にする。「まだ」は初回だけ |
| 条件（期間も）が 1 つ以上 | `filtered_empty` | 適用中の条件を見せ、個別に・まとめて外す（W-15）。作る導線は主にしない。期間だけの 0 件もここ |
| 直前に最後の 1 件を処理した | 片付いた（`empty`） | 結果を言う（「未確認の入金はすべて確認しました」）。次の画面への導線。作る導線は出さない |

- 読み込み前・取得に失敗したときは 0 件にしない（`loading`・`error`）。

## E-06 失敗の種類・置き場所・伝え方

問い：この失敗を、どこに、誰に、どう出すか。種類と置き場所はここが正。欄ごとの出し方は F-04、文は L-06。

| 種類 | 見分ける事実 | 置き場所 | 見せ方 |
| --- | --- | --- | --- |
| 入力の誤り | 送る前の検査で欄が分かる | 欄の直下。2 件以上は先頭に一覧 | F-04 が正 |
| 通信 | 応答なし・時間切れ・オフライン | 操作した所のすぐ近く。窓の中の操作は窓の中（窓は閉じない） | role=alert＋もう一度（E-07）。入力は残す |
| 権限 | 資格が無い | 画面の本体 | 理由と、誰に頼むか。再試行は出さない |
| 競合 | 開いた後に版が変わった | 保存の操作の近く | E-09 |
| 相手側の障害 | 画面の外の部品だけ失敗（郵便番号の補完、メールの送り先） | その部品の隣 | 「手で入れられます」。ほかを止めない |
| 一部失敗 | 1 操作で複数件のうち一部が失敗 | 結果の一覧（成功と失敗を分ける） | 「5件中4件を確認しました。1件は確認できませんでした」。失敗分だけ再試行 |

- 取得に失敗した画面全体は `ErrorState` を本体の位置に。裏の操作の失敗は短い知らせで、閉じるまで残す。原因が分からなくても、何をしようとして止まったかと次の一手を書く〔調査〕。
- **見ていない間の失敗**（書き出し、メールの送り先の障害）は、次に開いたとき一覧の行に「送れませんでした」の札と理由を残し、「今日やること」の件数に足す。期限に響く物は直るまで残す。短い知らせだけで終わらせない（EP-3）。

## E-07 再試行

根拠：EP-3・EP-6・W-25。問い：もう一度を出すか。自動で試すか。軸：①読むだけか書き込みか ②結果が分かるか ③何回続けて失敗したか

| 条件 | 選ぶもの |
| --- | --- |
| 読むだけ・初回表示で通信が失敗 | 自動で最大 2 回、1 秒・3 秒あけて。待ちの表示のまま。なお失敗なら失敗の表示と「もう一度読み込む」〔目安〕 |
| 読むだけ・表示中の更新が失敗 | 自動は 0 回。`stale` とやり直し |
| 書き込み（送る・記録・取り消す・確認） | 自動で再試行しない。手動の「もう一度」だけ |
| 書き込みの結果が分からない（時間切れ） | 再試行の前に状況を読み直す。反映済みなら「送れていました」。未反映なら「もう一度送る」。読み直しもできないなら「送れたか確認できません。請求書の一覧で確かめてください」。自動で再送しない |
| 手動が 3 回続けて失敗 | 「時間をおいて、もう一度お試しください」と問い合わせへの導線〔目安〕 |

- 入力の誤り・権限・見つからない・競合には再試行を出さず、直す・戻る・選ぶ導線を出す。

## E-08 確かめの窓か「元に戻す」か

根拠：EP-4。軸：①1 操作で戻せるか ②相手に届く・番号が付くか ③お金・番号・期限に関わるか ④1 日の回数。文は L-05。

| 条件 | 選ぶもの |
| --- | --- |
| 戻せる＋届かない＋お金・番号・期限に関わらない | 先に実行し 10 秒の「元に戻す」。窓なし〔調査〕〔試作〕 |
| 戻せない／届く／番号が付く | 窓。宛先・合計・期限は項目で、ボタンは「請求書を送る」「やめる」（やめる→主）。直前の 1 文で結果を言う〔調査〕 |
| 戻せる＋お金・番号・期限に関わる | 見せて裏で送る方式にしない。確定後に「元に戻す」。戻すときは記録を消さず履歴に「取り消しました」を足す〔原理〕 |
| 金額の食い違いを確定する | 窓にせず、その場に差額（符号つき）と理由で 2 択。黙って確定しない。確定後に「元に戻す」〔試作〕 |
| 1 日 10 回以上 | 窓なし。戻せないなら一覧で複数選んで 1 回の窓へ〔目安〕 |

- 窓は 1 操作 1 回。5 件以上〔目安〕は窓 1 回に件数と合計額。「元に戻す」が消えた後も、戻せる物は詳細に操作を残す（「入金の記録を取り消す」）。

## E-09 二重・同時編集・期限切れ

根拠：EP-4・EP-5・EP-6・W-09・W-27。問い：1 回しか効かず、別の人の更新を壊さず、期限が切れても入力が残るか。入力が残る規則と離れる確かめは F-09・F-10。

| 場面 | 決め方 |
| --- | --- |
| 送るを連打 | 押した瞬間から押したボタンだけ処理中。サーバーでも同じ操作は 1 回。完了後は戻るで再送しない |
| ログインの時間切れ（`session_expired`） | 切れる 2 分前〔目安〕に知らせ、延ばす操作を 1 つで出す（20 秒以上前、10 回以上延ばせる〔調査〕）。切れた後は、入り直すと入力が戻る〔調査〕 |
| 版が違い、変えた項目が重なる、またはお金・番号・期限の項目 | `conflict`。「別の人が HH:MM に更新しました」。違う項目だけ並べ（自分の値・相手の値）、「自分の内容で上書きする」「相手の内容を読み込む」。読み込む前に自分の入力を控えに残す。重ならない項目は黙って保存して「ほかの人の更新も含めて保存しました」 |
| 新規作成で、参照先（採番・取引先・設定）が入力中に変わった | 「上書き」は当てはまらない（上書き先の保存済みデータが無い）。違う項目を並べ、「この内容で保存する」「新しい○○を使う」から選ばせる。読み込む前に自分の入力を控えに残す〔試作〕 |
| 送る窓を開いた後に請求書が変わった | 窓の宛先・合計を差し替え「内容が更新されました。もう一度確かめてください」。確かめた物と違う物を送らない |

## E-10 途中の続きと、見つからない物

根拠：EP-3・W-06・W-26。問い：途中でやめた物に戻れるか。消された・無い物に来たらどうするか。

| 条件 | 選ぶもの |
| --- | --- |
| 2 段以上の流れ（はじめての設定） | 段を移るたびに入力を保存。次に開いたら続きの段から（`resumed`）。先頭に「前回の続きです。2段目から始めます」と、最初からやり直す操作。終わったら `done` からホームへ。続きの導線をメニューに残さない〔試作〕 |
| 存在しない id・削除済み | `not_found`。「見つかりません」＋一覧への導線。削除の記録があれば「削除されました（HH:MM）」。詳細で消した後は一覧へ置き換えて移る |
| 送った請求書 | 消さず「取り消し済み」で残し、`not_found` にしない。消せるのは下書きだけ〔試作〕 |
